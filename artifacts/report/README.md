# 已跑好的评估报告（不需要密钥即可查看）

`demo_eval_report.html` 是一份**完整跑完的评估报告**，双击即可打开。
它是自包含的静态 HTML——没有外部链接、没有脚本、没有网络请求。

## 这份报告展示什么

| 作业要求 | 在报告里的位置 |
|---|---|
| PDF 解析结果，包括正文和表格 | 「PDF 解析结果」小节（正文按条款结构列出，表 1 渲染为真 HTML 表格，合并单元格用 colspan/rowspan） |
| 至少 5 个问答结果，含表格题与无答案题 | 「逐题明细」 |
| 来源引用和自检结果 | 每题卡片里的引用与自检红绿 |
| 测试或评估脚本运行结果 | ① 索引层、按题型分组、对抗变异检出率 |
| **检索质量的实际数字** | ② 检索层：Recall@10 **100%**、MRR **0.950**、nDCG@10 **0.963**（n=10） |
| **噪声到什么强度开始不可靠** | ③ 噪声鲁棒性：0% / 2% / 7% 实际 CER 三档 |
| 延迟 | 顶部卡片：中位数与 p95 |

（第一项"从部署/启动开始的完整流程"报告覆盖不了——那是命令行的事，
见根 README 的快速开始。）

## 它跑的是什么

- **输入**：`artifacts/demo/demo_scan.pdf` —— 一份**合成件**，内容全部自撰，
  可以自由公开（两份真实文档都不能：GB/T 取自官方预览已承诺不再分发，
  另一份含个人信息）。
- **OCR 引擎**：`fixture` —— 读取预置结果，**不是真实模型识别**。
  所以这份报告证明的是**管线与格式**，不是识别能力。
- **生成模型**：**没有配**。走的是抽取式降级路径（答案由证据原文拼装）。
- **索引层基准**：`artifacts/demo/transcription.md`，由生成脚本从源常量
  程序化导出——对合成件而言那就是精确真值。

## 怎么复现

不需要任何模型密钥：

```powershell
uv run python tools/make_demo_artifact.py     # 重新生成合成件（可选）
uv run docqa ingest artifacts/demo/demo_scan.pdf --engine fixture `
    --fixtures-dir artifacts/demo/ocr --out out/demo
uv run docqa eval --doc out/demo/<产物目录> --golden data/golden/demo_qa.jsonl `
    --transcription artifacts/demo/transcription.md `
    --no-llm --noise-sweep 3 --report out/demo_report.html
```

`--no-llm` 不是可选项：不写它就会用 `.env` 里配的生成模型，
同一份代码两次跑出不同数字，报告也就不可复现了。

## 抽取式 vs 生成模型：现在是什么样

| 路径 | 通过 | 准确率 | 拒答精确率 | 拒答召回率 |
|---|---|---|---|---|
| 抽取式降级（本报告） | 11/13 | 84.6% | 1.00 | 1.00 |
| `deepseek-chat`，连跑三次 | 12/13 | 92.3% | 0.67 | 1.00 |

早先这里写过"配了生成模型反而更差（8/13、精确率 0.29）"。
那个数是在**修复前**测的，与现在的代码不可比：这一轮修复里有两处直接作用在
**批量评估**上——跨题泄漏的修复提示（一道题的自检失败提示会被下一题继承）、
引用条号真实性校验。没有做消融实验，所以这里只如实给"修完之后是什么样"，
不把差异精确归因到某一行代码。

现在唯一被拒错的一题是否定题（"本标准是否规定了键的材料牌号？"）——
正确答案是"未规定"，模型拒答了。这与真实文档上的表现一致：
**否定题是稳定短板**，不是随机波动。

真实文档（GB/T）上的对应数字见根 README 的「完成度自述」——
那里的报告**不入库**，因为含标准正文，与"不再分发"的承诺冲突。
