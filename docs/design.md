# 设计思路与被否决的方案

本文记录**为什么这么设计**，以及**哪些看起来很合理的方案被否决了、为什么**。
后者往往更能说明问题。

---

## 一、问题的实际形状

拿到作业后先做环境勘查，三个发现直接改变了方案：

**作业点名的 GB/T 1568 PDF 不在目录里。**

所以第一优先级是**解决数据，而不是写代码**——最终从国家标准全文公开系统的
公开预览中还原了 GB/T 1568-2008（4 页，含表 1：真条款号、真表格）。

> **这一条值得单独说**：如果我先埋头写管道，写完才发现没有表格题，
> 那才是真正的返工。**先确认数据能否支撑要求，再决定做什么。**

---

## 二、关键决策

### 1. PDF 类型判定：多信号取证，不用单一阈值

常见做法是"每页字符数 < N 就送去 OCR"。它会漏掉三种情况：

| 情况 | 单一阈值会怎样 |
|---|---|
| **伪文本层**（上次劣质 OCR 的残留） | 字符数达标 → 放过去 → 全文检索建立在一堆错字上 |
| **混合件**（90 页里夹 55 页扫描件） | 文档级均值可能仍然达标 → 整批漏判 |
| **干扰图** | "图像数 > 0 就是扫描件"会被 1×1 占位图带偏 |

改为逐页、多信号、留证据：可抽取字符数（**两个独立引擎交叉**）、
字体资源数、**绘制图像覆盖比**（从显示列表算，不数对象）、乱码文本层特征。

**一条硬不变量**：有真实文本层的页永远不送 OCR——已经能读到的文字再识别一次只会引入新错误。

> **这条曾经只是口号**：判定层认得出 TEXT 页，但管线里没有"从文本层取块"的实现，
> 于是这些页既没送 OCR、也没进索引——**内容被静默丢掉**，日志一切正常。
> 现在由 `ocr/textlayer.py`（`TextLayerEngine`，PyMuPDF `get_text("dict")` 取块）
> 顶上，TEXT 页走它、SCANNED/HYBRID 页照旧送识别模型；
> 跨引擎一致性校验只比"真的识别过"的页。
> 代价是文本层没有表格结构，复杂表格会退化成文本行——报告里会带
> `本页内容取自 PDF 原生文本层，未调用识别模型` 的告警，不静默冒充。

实测副产品：`/Font == 0` 这条信号**单独就足以判定纯扫描件**，比字符阈值更硬。

### 2. 位精确取图，而不是重新光栅化

扫描件的每一页本质上就是嵌在 PDF 里的位图。原样取出来喂给模型，
比"渲染一次再编码"少一道重采样——对 OCR 而言，任何重采样都只可能损失信息。

**实现时踩了坑**：`get_image_info()` 不传 `xrefs=True` 就**不返回 xref**，
拿不到 xref 就取不出原始位图，于是静默退化成光栅化。
表现是"位精确取图"从未真正生效，页图分辨率反而**低于**源文件。
代码没报错、测试没失败、日志显示成功——**只有看输出的数字才发现**。

### 3. 放大不等于变清晰

主文档原生 280 DPI。渲染到更高 DPI 只是**插值，不产生新信息**。

但放大确实可能改善 VLM 对小号中文字的**辨识率**——那是模型输入有效分辨率的问题。
所以 `upscale` 是一个**实验变量**，应当由 A/B 消融决定要不要开，
且只声称"帮助辨识"，**不声称"恢复精度"**。

> **现状如实说明**：这个消融**还没跑**——`--upscale` 只做到把取值记进
> `pages.json` 可溯源，没有自动对比机制。实验设计见
> [evaluation.md 第六之二节](evaluation.md)，那里也写了为什么没跑。

> 我最初的计划里写的是"默认 300 DPI、表格页升 400"，
> 依据是一组"400 DPI 使中文 CER 降至 5.7%"的数据。
> 后来发现那组数据来自**真实扫描在不同 DPI 下采集**，
> 而本项目的源文件本身就只有 200/280 DPI——**依据不成立，方案随之改掉**。

### 4. 条款感知切分 + 必须存在的退化路径

固定字数硬切会把条款从中间截断，且产生不了条号引用，追溯失效。
所以按文档自身的结构切，每个 chunk 带 `clause_path`。

**但必须设计退化路径**：短公文可能整篇是一段连续文字，没有任何标题结构。
这时条款切分会产出唯一一个 chunk，引用与检索双双退化。
所以识别不到结构时退回**句子窗口**，引用格式相应降级为 `[p.1 ¶3]`。

**退化不是缺陷，是必须被设计出来的路径**——真实客户文档里，
"没有结构"比"结构规整"要常见得多。

### 5. 检索用两条不需要模型的臂

向量检索需要 embedding 端点。一旦它成为必需项，评估结果在不同机器上就不可复现，
而且没有密钥的人根本跑不了评估。而"可复现"是本次交付的硬要求。

所以主力是两条纯词法的臂：

- **bm25_word**：jieba 分词后的词元级 BM25，对术语准；
- **bm25_char**：**字符二元组** BM25。中文没有词边界，二元组天然覆盖未登录词与生僻字，
  对人名、以及 OCR 把词切错的情况特别有效。

两条臂用 RRF 融合。RRF 只看排名、不看分数——不同量纲的分数本来就没法直接加权，排名可以。

### 6. 内容寻址缓存，而不是"旁路入口"

最初想提供 `--from-ocr-json`，让没有密钥的评审也能验证下游。
但**一份别人递进来的 JSON 与"手工录入全文"在性质上无法区分**——
作业明确禁止绕过解析。

改为**内容寻址缓存 + 哈希链 + 可重放**：

```
cache_key = sha256(image_sha256 ‖ provider ‖ model ‖ prompt_sha256 ‖ params)
```

缓存是 OCR 层的**正常工作方式**，不是特殊通道。三件套
（页图 + OCR 产物 + Provenance + 提示词原文）让整条链可以被审计、
并用自己的密钥重发完全相同的请求逐字比对。

> **一处必须说明的约束**：原设计打算把这条链**提交入库**，但本项目的两份真实文档
> 不能公开（GB/T 不再分发），所以真实文档的链**只存在于本地**。
> 改为提交一份**合成件**的完整链（`artifacts/demo/`）——评审无需密钥即可核对格式、
> 重算哈希、并用 fixture 引擎复现整条下游。**能复现的演示比不能复现的更有价值。**

缓存命中因此不是一句"信我"，而是一个能被独立检验的事实。

### 7. DOCX 没有"页"：抽象定位，而不是假装有页码

PDF 的页码是文件自身的事实；DOCX 的页码由 Word/WPS 的排版引擎、字体与纸张
共同决定，**同一份文件在两台机器上可以不同**。拿渲染出来的页码当引用锚点，
等于让引用不可复现——而这正是本项目最不能接受的。

所以定位被抽象成两种 `locator_kind`：

| 来源 | locator | 引用 | 证据头 |
|---|---|---|---|
| PDF | `page` | `[p.3 §3.6]` / `[p.3 ¶12]` | `（第 3 页 §3.6）` |
| DOCX | `paragraph` | `[§3.6 ¶4]` / `[¶4]` | `（§3.6 ¶4）` |

- `¶n` = 文档顺序第 n 个**非空正文块**（段落或线性化表格；标题计入；
  空段落不计），不是 Word 的段落数。每个 chunk 带 `para_no/para_end` 区间，
  `¶4` 落在区间内即映射到该 chunk。
- 一个超长段落会被切成多片，所有片共享同一个 `para_no/para_end` 与同一个
  渲染串。解析时把该段落号下的**全部** in-range chunk 收进一条引用的
  `evidence_chunk_ids`；数值落地、句级支撑与引用有效性都按这个集合比对。
  只认召回顺序第一片，会让事实落在后续片里的正确答案被判成幻觉并拒答。
- `Chunk.page_no` / `Citation.page_no` 改为 `int | None`：类型上就不允许把
  DOCX 当成"第 0 页"。`Citation.render()` 在 `page_no=None` 时**绝不产出
  `p.None`**，降级到段落模板或 `[?]`——一个看起来像引用、实际不可定位的
  字符串，比明说"不知道"更糟。
- 提示词、修复提示、自检的引用剔除正则都按同一份定位契约分支：DOCX 的
  `[§3.6 ¶4]` 若不被识别，3.6 与 4 会混进数值断言，让正确回答被判成幻觉。
- 对外序列化不只给渲染后的字符串：`AnswerBundle.to_dict()` 的每条引用同时带
  `locator_kind/section/para_no/para_end`，前端才能按 locator 分支定位；
  `section` 会剔除 `]` 与换行，避免破坏 `[...]` 语法。
- PDF 行为完全不变：新增字段全部带默认值，`PdfProfile` 保留为
  `SourceProfile` 的兼容别名，旧产物零改动可读。

### 8. 回答范围：strict 默认，hybrid 显式可选，模型知识不是证据

`strict` 是默认路径，引用、自检与拒答语义不动。`hybrid` 只解决一种需求——
"文档里确实没有，但用户想听通用知识"，并且必须由用户**显式选择**：

- 文档能支持的内容仍**逐句引用**；模型知识单独放在答案末尾的
  `【模型知识补充】` 段，**禁止引用、禁止声称文档写了**；
- **hybrid 正文句句可证**：新增 GATE `doc_sentence_support`——按**子句粒度**
  （`。！？!?；;，,：、` 与**所有视觉换行**：`\n`/`\r`/`\v`/`\f`/U+2028/U+2029/
  U+0085，引用标记归前一个子句）切分，**短句/逗号子句不豁免**；引用覆盖粒度是**句子**——
  子句自带标记时只用自己的标记，没有标记时借用**同句最后一个带尾部标记的子句**的
  引用（不跨句；尾标记后允许 0–2 个闭合包裹字符 `）` `)` `】` `」` `』` `》` `”`
  `’`，ASCII 引号不支持），借用后每个肯定子句仍必须**去掉引用后的归一化文本在所引证据里做
  段边界匹配**（不是任意子串）。归一化把**空白/表格 `|`/句读标点/引号括号当作段边界字符**——它们不进匹配
  核心，但保留在 source 里用于两侧边界判定；**单位、符号、限定词
  （mm/μm/℃/%/±/该/被/以上/不大于/不低于）保留在匹配核心**，任何差异都会被拒。
  连接词 `的/为/和/按` 只在**恰好构成 jieba token** 时删除（"行为/按钮/目的"不会
  被拆）。匹配要求**两侧段边界**（证据开头/结尾，或紧邻边界字符），紧邻中文/
  字母数字/单位符号即失败——**紧邻无空格的否定/限定前缀删除（不得/未/不/非）会
  失败**；但**空白/换行/表格单元分隔的否定前缀仍可能被单独引用**（`不得 | 使用铝`、
  `不得\n使用铝`、`不得 使用铝` 是已知残余 P2，不能当成绝对安全）。截断数值/单位
  （`0.5 mm` vs `±0.5 mm`）也会失败（不再使用 token recall / 词面重叠）。
  已知误杀还包括：句号在引号内（`“抗拉强度应大于等于 590 MPa。”[p.1 §3.1]`）可能
  被切分误杀、词中间截取会被段边界拒绝（只能从段/表格单元/词边界截取）、ASCII `.`
  阻止句末引用借用（`A，B [p.1 §3.1].`）、ASCII `!`/`?` 作为句边界会切开 `n!` 等
  写法。引用只保证**每个被覆盖子句逐字有据**，不保证片段相邻或同序（多标记并集可
  跨 chunk 拼接）。新增 GATE
  `doc_citation_marks`：每个 citation-like token 必须绑定到已解析 citation，
  `[p.99 §9.9]` 这类伪标记直接失败，不回退到全部 citations，且不因零引用放行而跳过；
  **文档原文自带 `[p.3]` 等引用字样时，逐字引用它可能被当作伪引用判失败**（需换
  片段或切 strict）。
  这是有意的安全取舍：正常改写、单位同义词（兆帕 vs MPa）、语序调整、符号/限定词
  差异都可能被拒；不过门会修复或拒答。strict 仍保留正常改写、只有 advisory
  `sentence_support`，检查列表与报告不变；
- **零引用只允许两种情形**：正文为空且确有补充段；或正文的每个分句都是**通用否定
  短句**——按 `；;。` 切分、每句匹配精确模板（文档/本标准/本文件/该文档/该标准 +
  可选 中/里/内 + 未/没有/并未 + 规定/提及/涉及/包含/收录/给出/找到/说明/列出
  + 可选 任何/相关/此项/该/上述 + 可选 内容/要求/信息/规定/说明/条款/事项
  + 可选句号），且**不含具体对象/谓词**。**具体否定 + 真实 citation 仍会被拒**
  （如「文档中未规定冲击韧性要求。[p.1 §3.1]」不在白名单，也几乎不可能是证据的
  逐字段）；**例外**：`文档中未规定。` 无论有无 citation 都可放行——它是模型"未
  找到"的判断声明，不是具体证据；具体结论仍必须引用或放补充段（附带的伪 citation
  仍被 `doc_citation_marks` 拒绝）。模型侧应要求"具体否定用通用否定短句，具体说明
  放补充段"；含肯定内容的正文仍必须逐句引用；
- **marker 只认单独成行**；证据里的同名串替换为 `【模型知识补充（文档原文）】`，
  不会劫持分段；**C0/C1 与 bidi 控制字符统一走 `models.sanitize_display_text`**
  （已含 U+202A–202E、U+2066–2069），覆盖
  `answer/model_knowledge/refusal_detail/citations[].quote/rendered/clause_label/
  candidates[].citation/checks[].detail/offenders/evidence.text`；API/CLI 的本地
  正则只是**幂等纵深**，其它绕过该函数的新通道需自行净化。文档正文与
  补充段都为空时，按**起草失败**处理（修复/拒答），不是一条成功响应；
- 文档明确未规定时，先写"文档中未规定"，再给补充段；
- hybrid **不因"文档没有 / 覆盖率低 / 检索分低"拒答**；但 `extraction_failed`
  在 hybrid 下**前置**：存在识别失败页且证据为空/覆盖率低，**或证据触及失败页**时
  直接拒答，**不调用模型**、不用知识替代。歧义与正文自检失败同样仍拒答；
- 未配置生成模型时 hybrid **不可用**（API 400 / CLI 配置错误 / 前端 disabled），
  不静默降级成 strict；
- 模型知识可能过时或错误，**不能作为合规/审计的唯一依据**；文档内容仍以引用为准。

取舍理由：把"有据"与"通用知识"混进同一个不可区分的答案，会让引用失去意义。
显式模式 + 显式分段（且补充段不可引用），是让读者一眼看出"哪句有据、哪句只是
模型说的"的最低成本做法。完整行为见 [`hybrid-mode.md`](hybrid-mode.md)。

### 9. 引用定位到页图：比例坐标 + 块级区域

引用除了"第几页 / 哪个条号"，还可以告诉读者"在这页的哪个位置"。实现上做了
两个刻意的选择：

1. **归一化成比例坐标（0~1），不在后端传像素/点。** 不同引擎的 `bbox` 单位不同：
   VLM / fixture 是**页图像素**，原生文本层（PyMuPDF）是**PDF 点**。若原样透传，
   前端就得知道每页用了哪个引擎、图按多少 dpi 渲染，任何 `upscale` 都会让框偏移。
   所以在 `load_result()` 阶段按引擎除以"页图像素"或"页面点"，统一成比例坐标，
   前端只用 `viewBox="0 0 1 1"` 的 SVG 覆盖在同一张图上，缩放/缩略图都不重算。
2. **只做到块级，不假装字符级。** 画出来的是"证据块覆盖的区域"，不是"这几个字"。
   VLM 的 bbox 精度与合并单元格等都会影响边界；把块级区域当字符级炫耀是误导。
   没有 bbox（如合成 fixture）或没有页图（DOCX / 文本层页）时**退回纯文本高亮**，
   绝不凭空画一个框。

代价是依赖 manifest 记录的那张渲染图尺寸；`upscale` 若与 OCR 输入不一致会让框
整体偏移（当前两者一致）。这条与前文"位精确取图"同源：图是证据的一部分，
不能一边换图一边沿用旧坐标。

## 三、被否决的方案

| 方案 | 否决理由 |
|---|---|
| **RAGAS / LLM-as-judge 作主指标** | 调研显示同类方法在**金融长文本/表格场景 Context Recall 误判率报告高达 37%**，且各工具同名指标定义互不等价。本文档正是表格密集。改为主指标全部确定性实现 |
| **多模型投票共识** | 一个无法证伪的标记——不报错也不报对的数字——**比没有标记更糟**。改为窄域重抽取 + 差异比对，并要求它**在评估里实测精确率后**才上线 |
| **句级支撑度直接当 gate** | 它依赖中文分词与一个阈值，而本项目没有足够标注数据校准那个阈值。未校准的阈值产生的假警报会训练使用者忽略这个信号。**降级为咨询性指标**，实测达标后才考虑升格 |
| **给每个场景写一个切分器类** | 过度设计。一个 profile 驱动的切分器 + 正则列表就够，多出来的抽象只增加维护面 |
| **用 Docker 保证复现** | 在 Windows + uv 组合下成本高。`uv.lock` + 脚本已经能保证复现 |
| **两个通用 provider 之外再加本地 OCR** | 数据不能出内网时确实需要，但当前环境下装不上且模型体积与"三条命令可复现"冲突。改为**预留注册位**，并把 Python 钉在 3.12 保住接入可能 |
| **UI 做 bbox 级证据高亮** | 早期否决：VLM 的 bbox 质量不可靠，字符级精确定位会误导。**2026-11 修订**：改为**块级页图高亮**——只画"证据块在页面的哪一区域"（比例坐标），并保留纯文本回退与"块级而非字符级"的明确说明；读者对照原文核对，而不是被虚假的像素精度误导。见 §9 |

## 四、几处刻意的"不完美"

这些不是没想到，是明确选择不做，理由如下：

| 项 | 为什么不做 |
|---|---|
| 学习型拒答分类器 | 没有训练数据。一个可审计的分数阈值 + 覆盖率判据更实在 |
| 多轮对话 | 作业场景是单轮事实查询，加了只是增加状态管理复杂度 |
| 表格跨页合并 | 主文档的表在一页内。跨页续表是金融场景的真需求，已在迁移文档里列为待办，但**不做没验证过的实现** |
| 向量检索 | 见决策 5。已留第三臂接口，配置打开即可 |

**"没做"和"做不了"要分开说**，这也是 README 里"完成度自述"单独列一节的原因。

## 五、数据流

```
PDF / DOCX
 │
 ├─ detect ──→ SourceProfile（逐页判定 + 信号证据 + 双引擎交叉；
 │                DOCX 走 source_type="docx"、unit_count=N、page_count=0）
 │                │
 ├─ render ──→ PageImage（位精确取图，记录原生 DPI 与哈希；DOCX 不适用）
 │                │
 ├─ ocr ─────→ OcrPage（结构化块 + 表格网格 + 溯源；DOCX 原生文本不调用）
 │   │            │
 │   │            └─ cache：内容寻址 + 提示词哈希 + Provenance
 │   │
 │   └─ spotcheck ──→ needs_review 标记（跨引擎不一致）
 │
 │
 ├─ chunk ───→ Chunk（条款路径 / 表格原子化 / 句子窗口退化；
 │              locator_kind=page 或 paragraph，DOCX 带 ¶n 区间）
 │
 └─ index ───→ HybridIndex（双 BM25 臂 + RRF + 表格路由）
                  │
                  └─ qa ──→ QaAgent（检索→起草→自检→修复→放行/拒答）
                              └─→ AnswerBundle（答案+引用+自检+轨迹+用量；
                                  引用按 locator 渲染：[p.3 §3.6] 或 [§3.6 ¶4]）
```

每一步的产物都独立落盘（`profile.json` / `pages.json` / `ocr.json` /
`chunks.jsonl` / `manifest.json`），所以**出了问题能一眼看出是哪一步的锅**。

## 六、如果重来一次

- **更早确认数据能否支撑作业要求**。这次是运气好，从公开预览里还原出了国标；
  如果还原不出来，整个方案的形状会完全不同；
- **一开始就给"输出的数字"写断言**。三处真 bug 里有两只（xref 缺失、点/像素混淆）
  都是"代码不报错但数字不对"，本可以更早发现；
- **把"不确定项"当作一等产物**。读者 B 提出的三处判读不确定
  （冒号全半角、`≥` vs "大于等于"、破折号类型）本身就是 OCR 错误的真实来源，
  一开始就记下来比事后补要有价值得多。
