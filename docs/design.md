# 设计思路与被否决的方案

本文记录**为什么这么设计**，以及**哪些看起来很合理的方案被否决了、为什么**。
后者往往更能说明问题。

---

## 一、问题的实际形状

拿到作业后先做环境勘查，三个发现直接改变了方案：

**作业点名的 GB/T 1568 PDF 不在目录里。**

所以第一优先级是**解决数据，而不是写代码**——最终从国家标准全文公开系统的
公开预览中还原了 GB/T 1568-2008（4 页，含表 1：真条款号、真表格）。

> **这一条值得单独说**：如果我先埋头写管道，写完才发现没有表格题，
> 那才是真正的返工。**先确认数据能否支撑要求，再决定做什么。**

---

## 二、六个关键决策

### 1. PDF 类型判定：多信号取证，不用单一阈值

常见做法是"每页字符数 < N 就送去 OCR"。它会漏掉三种情况：

| 情况 | 单一阈值会怎样 |
|---|---|
| **伪文本层**（上次劣质 OCR 的残留） | 字符数达标 → 放过去 → 全文检索建立在一堆错字上 |
| **混合件**（90 页里夹 55 页扫描件） | 文档级均值可能仍然达标 → 整批漏判 |
| **干扰图** | "图像数 > 0 就是扫描件"会被 1×1 占位图带偏 |

改为逐页、多信号、留证据：可抽取字符数（**两个独立引擎交叉**）、
字体资源数、**绘制图像覆盖比**（从显示列表算，不数对象）、乱码文本层特征。

**一条硬不变量**：有真实文本层的页永远不送 OCR——已经能读到的文字再识别一次只会引入新错误。

实测副产品：`/Font == 0` 这条信号**单独就足以判定纯扫描件**，比字符阈值更硬。

### 2. 位精确取图，而不是重新光栅化

扫描件的每一页本质上就是嵌在 PDF 里的位图。原样取出来喂给模型，
比"渲染一次再编码"少一道重采样——对 OCR 而言，任何重采样都只可能损失信息。

**实现时踩了坑**：`get_image_info()` 不传 `xrefs=True` 就**不返回 xref**，
拿不到 xref 就取不出原始位图，于是静默退化成光栅化。
表现是"位精确取图"从未真正生效，页图分辨率反而**低于**源文件。
代码没报错、测试没失败、日志显示成功——**只有看输出的数字才发现**。

### 3. 放大不等于变清晰

主文档原生 280 DPI。渲染到更高 DPI 只是**插值，不产生新信息**。

但放大确实可能改善 VLM 对小号中文字的**辨识率**——那是模型输入有效分辨率的问题。
所以 `upscale` 是一个**实验变量**，应当由 A/B 消融决定要不要开，
且只声称"帮助辨识"，**不声称"恢复精度"**。

> **现状如实说明**：这个消融**还没跑**——`--upscale` 只做到把取值记进
> `pages.json` 可溯源，没有自动对比机制。实验设计见
> [evaluation.md 第六之二节](evaluation.md)，那里也写了为什么没跑。

> 我最初的计划里写的是"默认 300 DPI、表格页升 400"，
> 依据是一组"400 DPI 使中文 CER 降至 5.7%"的数据。
> 后来发现那组数据来自**真实扫描在不同 DPI 下采集**，
> 而本项目的源文件本身就只有 200/280 DPI——**依据不成立，方案随之改掉**。

### 4. 条款感知切分 + 必须存在的退化路径

固定字数硬切会把条款从中间截断，且产生不了条号引用，追溯失效。
所以按文档自身的结构切，每个 chunk 带 `clause_path`。

**但必须设计退化路径**：短公文可能整篇是一段连续文字，没有任何标题结构。
这时条款切分会产出唯一一个 chunk，引用与检索双双退化。
所以识别不到结构时退回**句子窗口**，引用格式相应降级为 `[p.1 ¶3]`。

**退化不是缺陷，是必须被设计出来的路径**——真实客户文档里，
"没有结构"比"结构规整"要常见得多。

### 5. 检索用两条不需要模型的臂

向量检索需要 embedding 端点。一旦它成为必需项，评估结果在不同机器上就不可复现，
而且没有密钥的人根本跑不了评估。而"可复现"是本次交付的硬要求。

所以主力是两条纯词法的臂：

- **bm25_word**：jieba 分词后的词元级 BM25，对术语准；
- **bm25_char**：**字符二元组** BM25。中文没有词边界，二元组天然覆盖未登录词与生僻字，
  对人名、以及 OCR 把词切错的情况特别有效。

两条臂用 RRF 融合。RRF 只看排名、不看分数——不同量纲的分数本来就没法直接加权，排名可以。

### 6. 内容寻址缓存，而不是"旁路入口"

最初想提供 `--from-ocr-json`，让没有密钥的评审也能验证下游。
但**一份别人递进来的 JSON 与"手工录入全文"在性质上无法区分**——
作业明确禁止绕过解析。

改为**内容寻址缓存 + 哈希链 + 可重放**：

```
cache_key = sha256(image_sha256 ‖ provider ‖ model ‖ prompt_sha256 ‖ params)
```

缓存是 OCR 层的**正常工作方式**，不是特殊通道。三件套
（页图 + OCR 产物 + Provenance + 提示词原文）让整条链可以被审计、
并用自己的密钥重发完全相同的请求逐字比对。

> **一处必须说明的约束**：原设计打算把这条链**提交入库**，但本项目的两份真实文档
> 不能公开（GB/T 不再分发），所以真实文档的链**只存在于本地**。
> 改为提交一份**合成件**的完整链（`artifacts/demo/`）——评审无需密钥即可核对格式、
> 重算哈希、并用 fixture 引擎复现整条下游。**能复现的演示比不能复现的更有价值。**

缓存命中因此不是一句"信我"，而是一个能被独立检验的事实。

## 三、被否决的方案

| 方案 | 否决理由 |
|---|---|
| **RAGAS / LLM-as-judge 作主指标** | 调研显示同类方法在**金融长文本/表格场景 Context Recall 误判率报告高达 37%**，且各工具同名指标定义互不等价。本文档正是表格密集。改为主指标全部确定性实现 |
| **多模型投票共识** | 一个无法证伪的标记——不报错也不报对的数字——**比没有标记更糟**。改为窄域重抽取 + 差异比对，并要求它**在评估里实测精确率后**才上线 |
| **句级支撑度直接当 gate** | 它依赖中文分词与一个阈值，而本项目没有足够标注数据校准那个阈值。未校准的阈值产生的假警报会训练使用者忽略这个信号。**降级为咨询性指标**，实测达标后才考虑升格 |
| **给每个场景写一个切分器类** | 过度设计。一个 profile 驱动的切分器 + 正则列表就够，多出来的抽象只增加维护面 |
| **用 Docker 保证复现** | 在 Windows + uv 组合下成本高。`uv.lock` + 脚本已经能保证复现 |
| **两个通用 provider 之外再加本地 OCR** | 数据不能出内网时确实需要，但当前环境下装不上且模型体积与"三条命令可复现"冲突。改为**预留注册位**，并把 Python 钉在 3.12 保住接入可能 |
| **UI 做 bbox 级证据高亮** | VLM 给的 bbox 质量不可靠，画出来会误导。改为 **chunk 级高亮**——诚实且便宜 |

## 四、几处刻意的"不完美"

这些不是没想到，是明确选择不做，理由如下：

| 项 | 为什么不做 |
|---|---|
| 学习型拒答分类器 | 没有训练数据。一个可审计的分数阈值 + 覆盖率判据更实在 |
| 多轮对话 | 作业场景是单轮事实查询，加了只是增加状态管理复杂度 |
| 表格跨页合并 | 主文档的表在一页内。跨页续表是金融场景的真需求，已在迁移文档里列为待办，但**不做没验证过的实现** |
| 向量检索 | 见决策 5。已留第三臂接口，配置打开即可 |

**"没做"和"做不了"要分开说**，这也是 README 里"完成度自述"单独列一节的原因。

## 五、数据流

```
PDF
 │
 ├─ detect ──→ PdfProfile（逐页判定 + 信号证据 + 双引擎交叉）
 │                │
 ├─ render ──→ PageImage（位精确取图，记录原生 DPI 与哈希）
 │                │
 ├─ ocr ─────→ OcrPage（结构化块 + 表格网格 + 溯源）
 │   │            │
 │   │            └─ cache：内容寻址 + 提示词哈希 + Provenance
 │   │
 │   └─ spotcheck ──→ needs_review 标记（跨引擎不一致）
 │
 │
 ├─ chunk ───→ Chunk（条款路径 / 表格原子化 / 句子窗口退化）
 │
 └─ index ───→ HybridIndex（双 BM25 臂 + RRF + 表格路由）
                  │
                  └─ qa ──→ QaAgent（检索→起草→自检→修复→放行/拒答）
                              └─→ AnswerBundle（答案+引用+自检+轨迹+用量）
```

每一步的产物都独立落盘（`profile.json` / `pages.json` / `ocr.json` /
`chunks.jsonl` / `manifest.json`），所以**出了问题能一眼看出是哪一步的锅**。

## 六、如果重来一次

- **更早确认数据能否支撑作业要求**。这次是运气好，从公开预览里还原出了国标；
  如果还原不出来，整个方案的形状会完全不同；
- **一开始就给"输出的数字"写断言**。三处真 bug 里有两只（xref 缺失、点/像素混淆）
  都是"代码不报错但数字不对"，本可以更早发现；
- **把"不确定项"当作一等产物**。读者 B 提出的三处判读不确定
  （冒号全半角、`≥` vs "大于等于"、破折号类型）本身就是 OCR 错误的真实来源，
  一开始就记下来比事后补要有价值得多。
