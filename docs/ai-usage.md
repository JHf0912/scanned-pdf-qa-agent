# AI 工具使用说明

作业要求"如实说明 AI 使用情况"并"对结果负责"。这份文档记录的就是这两件事：
**哪些环节用了 AI、我怎么校验它、以及它错在哪里、我怎么发现的。**

## 二、AI 出错、被我抓住的地方（这是本文件最重要的部分）

用 AI 不是问题，**不校验才是问题**。以下几处都是给出了看似合理、实际错误的结论——
前三处来自 AI 代理，第四处是我自己（我即 AI）在使用 AI 时犯下的。

### 1. 表 1 的数值被 AI 记错了

调研阶段，一个 AI 代理给出了 GB/T 1568-2008 表 1 的 AQL 值，声称：
"半圆键 键宽 b = **1.5**"、"楔键 键长 L = **—**"。

**它自己在同一份报告里警告过**："该表列对齐不可靠，不要硬编码，务必核对页图。"

我按它的警告去核对了页图。**两轮独立阅读都确认实际值是：**
半圆键 键宽 b = **1.0**、楔键 键长 L = **4**。

> 这是整个项目里最有价值的一次校验。它证明了：
> **二手文本不可信，视觉证据优先。** 这条结论后来直接变成了系统的设计原则——
> 数字必须能追到页面上，而不是追到某个转述里。

### 2. AI 把"页数"数错了，我也跟着错了

我最初用字节 grep 数 `/Type /Page`，得到 2 页并写进了计划。
一个评审代理指出应该是 1 页。重新核对 `/Count 1` 确认**是我错了**——
我的正则 `[^s]` 会吞掉后一个字符，产生重复匹配。

教训：**用工具的方式错了，工具给出的答案再确定也没用。**

### 3. AI 编造了一条环境事实

一个代理声称这份 PDF 是 ImageMagick 生成的，依据是 `/Creator`、`/Producer` 字段。
我直接读原始字节核对：**整份文件根本没有 `/Producer` 或 `/Creator` 字段**，
ImageMagick 字样出现 0 次。该结论不成立。

（真实情况是：`/CreationDate` 是当天，说明它是程序生成的文件——这一点成立，但依据完全不同。）

### 4. 一次干跑抓出九个缺陷，其中三个会直接毁掉首次运行

代码写完后我让一个独立代理审计了**从未被执行过**的三条命令
（`ingest` / `eval` / `serve`），再用一份自造文档真跑了一遍。
结果抓到 9 个缺陷，**没有一个是靠读代码看出来的**：

| 缺陷 | 为什么危险 |
|---|---|
| 控制台入口绑到了 `app` 而不是 `main` | **精心写的错误处理与退出码全是死代码**。用户没填密钥就跑 `ingest`，看到的是一段 traceback，而不是那段"缺哪个变量、去哪配、有哪些替代路径"的提示 |
| `pages=targets or None` | 空列表被当成"渲染全部页"→ **纯文本 PDF 会被整本送去 OCR**，违反自己写明的硬不变量，还白花钱 |
| `eval` 把每道题回答两遍 | 取样一遍、评估一遍 → **每次 eval 的 API 花费与耗时翻倍** |
| 报告读 `question`、写入方写 `questions` | 报告每条卡片显示 `D1` 而不是问题原文。**测试没抓到**——断言的问题串确实在 HTML 里，只是在文末的原始 JSON dump 中，是个假阳性断言 |
| 摘要崩溃导致报告没写出 | 摘要里一个未定义变量让 `eval` 直接挂掉，报告与 JSON 一个字都没写——**而那正是"第一次跑真实评估"** |
| `--json` 输出带 ANSI 高亮 | 一个叫 `--json` 的开关产不出能被 `json.loads` 解析的内容 |

**这一轮的教训比前面几轮更硬**：前几轮的 bug 还只是"数字不对"，
这一轮有四个是"**代码不报错、测试全绿、但功能整体失效**"。
唯一的发现方式就是**把每一条命令真的跑一遍**。

### 6. AI 写的代码有三处真 bug，全靠"跑一次"暴露

| 缺陷 | 怎么发现的 | 为什么重要 |
|---|---|---|
| `get_image_info()` 不传 `xrefs=True` 就拿不到 xref | 打印渲染结果，发现 `native=False` | "位精确取图"从未真正生效，页图分辨率反而**低于**源文件 |
| `img_doc[0].rect` 返回的是**点**不是像素 | 输出的 DPI 是 267 而不是 200 | 二次换算，物理尺寸算错 |
| 日志打码漏了密钥（`sk-` 未被匹配） | 看日志输出，发现 `api_key=sk-EXAMPLE-NOT-A-REAL-KEY-0000` 是明文 | 密钥会进日志文件。**后来的处理是：不再打码，而是从源头不把密钥写进日志**——擦拭只能覆盖想得到的形态（当初那版正则就没匹配上），而且会让人放松 |

第 1、2 条尤其说明问题：**代码没报错、测试没失败、日志显示"成功"**，
只是结果悄悄变差了。如果我不看输出、只看退出码，这两条会一路带到交付。

## 三、金标基准是怎么做的（双人独立阅读）

金标集是**衡量系统的标尺**，它自己错了，后面所有指标都没有意义。所以：

1. **读者 A（我）**：直接读渲染出的页图，写出转写与问答对；
2. **读者 B（另一个独立会话）**：只给两张页图，
   **并明确要求"不得读取该目录下的任何其它文件"**，
   避免被读者 A 的结果锚定；
3. **逐字比对**，分歧处回到图上看图裁决；
4. 只从**裁决后**的文本派生问答对。

**结果：两轮对表 1 的每个数值完全一致**——这也再次确认了第 1 节里那个 AI 错误。

读者 B 还提出了三处**真实的判读不确定**（扫描件上确实有歧义），已如实记录在
`data/golden/transcription.md`：

- `1:100` 的冒号是全角还是半角；
- 3.1/3.5 的"大于等于"是汉字还是符号 `≥`；
- 表 1 中的"不适用"标记是 em dash 还是全角连接号。

**这些不确定项本身就是 OCR 错误的真实来源**，所以它们没有被抹掉，
而是作为已知风险写进了评估文档。

## 四、防"用答案考试"的机械约束

金标是标尺，**绝不能变成管线的输入**——那样评估就变成了用答案考试，
而且失败是静默的：指标会变得非常好看，没有任何迹象表明出了问题。

所以我把它做成了**代码里的硬约束**，而不是流程约定：

```python
# src/docqa/pipeline.py
assert_not_golden(pdf_path)   # ingest 拒绝读取 data/golden/ 下的任何路径
```

靠人记得的事情早晚会忘。`tests/test_integration.py::TestGoldenIsolation` 守着这条。

## 五、我否决掉的 AI 建议

负责任地使用 AI，也包括**不采纳**它。

| 建议 | 来源 | 为什么否决 |
|---|---|---|
| 用 RAGAS / LLM-as-judge 做主指标 | 调研 | 调研同时显示：该框架在**金融长文本/表格场景 Context Recall 误判率高达 37%**。我们的文档正是表格密集。改为主指标全部确定性实现 |
| 做"多模型投票"共识机制 | 方案设计 | 一个无法证伪的标记（不报错也不报对的数字）比没有标记更糟。改为**窄域重抽取 + 差异比对**，并要求它在评估里**实测精确率**后才上线 |
| 用固定字符数切分 | 初版设想 | 会把条款从中间截断，且产生不了条号引用，追溯失效 |
| 渲染到 400 DPI"提升精度" | 我的初版计划 | 源文件原生就是 200/280 DPI，**放大是插值、不产生新信息**。改为默认原生 + 可配放大 + A/B 实测，且只声称"帮助辨识"不声称"恢复精度" |
| 用 `--from-ocr-json` 作为无密钥旁路 | 我的初版计划 | 一份来历不明的 JSON 与手工录入全文无法区分。改为**内容寻址缓存 + 哈希链 + 可重放**，让产物可被独立验证 |

## 六、我做的关键决策（AI 只提供证据，不替我选）

六个影响架构的选择，全部由我拍板：

1. **主文档改用 GB/T 1568**——作业点名的那份 PDF 不在目录里，而这份标准含真条款与真表格；
2. **OCR 走 VLM API + 适配层**，并保留本地引擎的接入位（Python 钉 3.12）；
3. **核心数值不交给单一来源**：加跨引擎交叉校验；
4. **DPI 默认原生**，放大只作实验变量；
5. **交付形态**：CLI + Web UI + 静态 HTML 报告；
6. **隐私处理**：公开仓库 + 不提交原始 PDF。

## 七、结论

AI 在这个项目里的作用是**放大执行力**，不是**替代判断**：

- 它帮我完成了环境勘查、方案调研、大量模块编码、文档起草；
- 但它给出的**每一条事实性结论都需要核对**——几处错误大多是"事实"层面的，
  而且都写得很自信；
- **四个真 bug 全部是"跑一次看结果"发现的**，没有一个是靠读代码看出来的。

所以这个项目里我最想强调的一条工程习惯是：
**不要只看它说成功，要看它给出的数**。本项目最初的"位精确取图"就是这样
——日志说成功、测试全绿，实际却悄悄降级成了光栅化，页图分辨率还低于源文件。
