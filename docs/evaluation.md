# 测试与评估方法

本文给出**每个指标的定义、公式、样本量与已知局限**。

刻意不使用 RAGAS 一类的现成框架，理由在文末"为什么不引入 RAG 评估框架"一节。
一句话概括：它们的主指标基于 LLM 评委，而调研显示同类方法在
**金融长文本/表格场景下 Context Recall 的误判率报告高达 37%**，
且不同工具的"Faithfulness"定义互不等价。本文档正是表格密集的。

---

## 一、三层评估体系，以及为什么是这个顺序

```
① 索引层（上下文可信度）  ← 先报这一层
        ↓
② 检索层
        ↓
③ 生成层
```

**顺序不是随意的。** 检索到的内容本身是错的，后面两层再漂亮也没有意义。
多数 RAG 评估框架把索引层当作既定事实，而扫描件场景里它恰恰最致命——
`DA/T 77—2019` 之所以要为 OCR 准确率单独立标准，正是因为下游的一切都建在它上面。

所以报告里 ① 层排在最前面，UI 上也把低置信度区域显式暴露出来。

---

## 二、① 索引层（上下文可信度）

### 字符错误率 CER

```
CER = (S + D + I) / N        N = S + D + C（参考文本字符数）
```

中文没有词边界，**必须按字符算**。两个容易踩的坑：

1. **不能按空格分词**。整句话会被当成一个 token，CER 恒为 0 或 1。
   本实现自己实现了 Levenshtein 距离，核心算法可见可测。
2. **必须先做繁简归一**。OCR 可能输出繁体变体，不归一会被算成替换错误、虚高 CER。
   用 `zhconv` 处理。

**同时报两个 CER**：

| 指标 | 口径 | 用途 |
|---|---|---|
| 归一化 CER | 去标点、繁简统一、全角转半角 | 可与公开数字比较 |
| **符号敏感 CER** | 保留标点、单位、符号 | **抓问答系统真正需要抓的错误** |

第二个是刻意加的。国标里 `≤`、`%`、`±AT8/2`、`1:100`、`GB/T 11334—2005`
都是承载语义的——去掉标点算 CER，恰好会掩盖这类错误。

### 参照值

| 来源 | 要求 |
|---|---|
| `DA/T 77—2019`（国家档案局，档案行业标准） | 印刷体中文/数字/英文识别准确率 **≥ 95%** |
| 中文数字化招标常见要求 | **≥ 99%**（部分要求 99.99%） |
| 行业经验值 | 干净印刷体 CER < 1%；1–3% 可用但需标注；> 3% 需重扫或转人工 |

**本项目目标：CER ≤ 1%**（字符准确率 ≥ 99%）。

> 诚实说明：`DA/T 77—2019` 是**档案行业标准（DA/T）而非国标**，
> 且我没有找到针对"国标扫描件"的公开 CER 基准。
> 上述目标是"行业标准下限 + 招标常见要求"的综合，不是某个可引用的 benchmark。

### 表格单元格准确率

按**单元格**比对（行、列对齐正确才算对），并单独报告**维度是否匹配**。
行列数不一致时不强行对齐——那只会产生一个好看但无意义的数字。

### 数值字段准确率

比 CER 更贴近业务的一层：参考文本里的每个数值，是否在结果中原样出现。

一个字符之差（`1.0` 与 `1.5`）在 CER 上只值 1/50，**在业务上却是完全错误的答案**。
所以数值字段单独度量，并给出 `missing` / `spurious` 明细。

## 三、② 检索层

| 指标 | 说明 |
|---|---|
| Recall@k | 相关片段被召回的比例 |
| MRR | 第一个相关片段的排名倒数 |
| nDCG@k | 考虑排序位置的折扣累积增益 |

**必须按题型分组报告。** 总体 Recall 会被数量多的事实题拉高，
掩盖表格题的真实短板——而表格题恰是本项目最难的一类。

### 已知局限（如实写明）

主文档只有 4 页、约 10–15 个 chunk。
**在这个规模上，Recall@k 与 MRR 没有统计意义**——
Recall@1 的随机基线就有 1/10。

处理方式不是道歉，而是**换评估单位**：

- 检索指标标注为"**管路连通性检查**"，并附 Wilson 区间，**不作为检索质量证据**；
- 真正承担统计功效的是**字符、单元格、变异、噪声样本**这几个单位；
- 同时给出**扩容协议**：放入 50 页标准或金融文档后重跑的命令与指标集。

先说出弱点，比等评审发现更值钱。

## 四、③ 生成层

| 指标 | 定义 | 是否需模型 |
|---|---|---|
| 引用有效率 | 引用的 chunk 真实存在且本次确实召回 | 否（确定性） |
| **数值落地率** | 答案中每个数字/文号都能在所引证据中原样找到 | 否（确定性） |
| 条款一致性 | 答案声称的条号与证据的条号自洽 | 否（确定性） |
| **上下文利用率** | 被引 chunk 数 / 召回 chunk 数 | 否（确定性） |
| 句级支撑度 | 与证据有实质重叠的句子占比 | 否（启发式） |
| 拒答精确率 / 召回率 | 该拒的拒了没、不该拒的别拒 | 否 |
| 成本 / 延迟 | `cost/query`、p50、p95 | 否 |

上下文利用率虽然便宜，信号却很强：**召回 6 条只引用 1 条，说明检索基本没起作用。**
参考资料给出的生产告警阈值是 < 40%。

### 一个必须说清楚的区分

**数值落地校验的是"答案是否忠实于证据"，不是"证据是否为真"。**

如果 OCR 把 `15号` 读成 `13号`，模型照抄 `13号`，数值落地**会通过**，
系统于是自信地给出一个错误答案。

| 威胁 | 机制 | 落在哪 |
|---|---|---|
| 模型编造内容 | 引用有效性 + 数值落地 + 条款一致性 | `qa/verify.py`（gate） |
| **证据被识别错** | 跨引擎交叉校验 + 低置信度标记 + `EXTRACTION_FAILED` 拒答 | `ocr/spotcheck.py` + `qa/policy.py` |

把这两件事混为一谈，是"看起来做了自检、实际没防住"的典型原因。

## 五、对抗变异套件：让"我做了自检"变得可证伪

"我做了自检"本身无法被检验。要让它可证伪，就得**造出已知的错误，看自检抓不抓得住**。

对每个正确答案注入变异，断言验证器必须拒绝，并按类型报检出率：

| 变异类型 | 对应真实失败模式 | 由哪条检查负责 |
|---|---|---|
| `number` | 把 590 改成 950 | numeric_grounding |
| `unit` | 把 MPa 改成 kPa（读起来完全合理） | numeric_grounding |
| `docid` | 把 GB/T 11334—2005 改成 2006 | numeric_grounding |
| `clause` | 把 3.6 说成 3.5（串条） | clause_consistency |
| `citation` | 删掉引用 | citation_validity |
| `fabricate` | 凭空加一句证据里没有的话 | **（无专门机制）** |

最后一行是刻意留的：**检出率低不代表自检没用，而说明该类错误超出了现有检查的设计范围。**
报告里按类型分开列并注明各自的责任机制，就是为了让缺口可见。

这件事还有一个别的测试做不到的性质：**它不受语料规模限制。**
主文档只有 4 页，但一页素材就能生成 20+ 个变异样本，样本量是够的。

## 六、OCR 噪声鲁棒性：量化"证据被污染时系统会怎样"

`eval/noise.py` 注入真实的 OCR 失败模式：

- **形近字**：键/健、未/末、己/已、日/曰 —— 替换后文本依然通顺，这正是它难被发现的原因
- **数字混淆**：0/O、1/l、5/S、8/B —— 单位与公差最怕这个
- **丢字 / 多字**
- **空白错位**

按噪声强度 × 随机种子扫描，画出退化曲线。用**固定种子保证可复现**——
不可复现的噪声实验，那条曲线就没有意义。

**预期结论（也是本设计要暴露的）**：噪声升高到某个程度后，
接地管线会**照着被污染的证据给出错误答案，并且通过全部数值落地校验**。

这不是缺陷，是这类系统的固有边界——**污染之下系统无从知道真相**。
所以这个实验的产出不是"我们做得很好"，而是**"噪声到达什么强度时系统开始不可靠"**，
并据此给出工程应对：高风险字段转人工复核、跨引擎交叉校验、低置信度标记。

## 六之二、DPI / upscale 消融：设计好了，但**没有跑**

`render.upscale` 是一个**实验变量**，默认 1.0（用页面原生 DPI）。
这一节写清它该怎么量——以及为什么到现在还没有数字。

### 要回答的问题

源文件本身就 280 / 200 DPI。渲染到更高 DPI 只是**插值，不产生新信息**，
所以它能影响的只有一件事：VLM 对**小号中文字**的辨识率
（输入有效分辨率的问题）。因此实验要问的是
"放大是否改善辨识"，**不是**"放大是否恢复精度"——这两句话不能混。

### 实验设计

| 项 | 取值 |
|---|---|
| 自变量 | `upscale ∈ {1.0, 1.5, 2.0}` |
| 因变量 | 索引层：归一化 CER、符号敏感 CER、数值字段召回、表格单元格准确率 |
| 控制 | 同一提示词版本、同一模型、`temperature=0`、逐页对齐同一份转写基准 |
| 判定 | 若 2.0 相对 1.0 的 CER 改善落在噪声内（按 Wilson 区间判），就**保持 1.0**——多花的是 token 与延迟 |

命令形态已经具备（`--upscale` 会把取值记进 `pages.json`，可溯源），
缺的是**把三档串起来自动跑并汇总的脚本**。

### 为什么没跑

如实说：**脚本没写**。三档 × 4 页 × 两次识别（含第二引擎）的编排不复杂，
但目前 `--upscale` 只做到"记录了取值"，没有对比机制。
README 的完成度自述里把这一点列为未完成项，而不是宣称"框架已就绪"。

### 一条被推翻的旧依据

> 最初的计划写的是"默认 300 DPI、表格页升 400"，依据是一组
> "400 DPI 使中文 CER 降至 5.7%"的数据。后来发现那组数据来自
> **真实扫描在不同 DPI 下采集**，而本项目的源文件本身只有 200/280 DPI——
> **依据不成立，方案随之改掉**。

留着这段是因为它说明了一件事：**指标的适用边界比指标本身更重要。**
同一组数字，换个前提就是错的。

## 七、回归与基线

- `docqa eval --baseline <json>` 在任何指标下滑时**非零退出**（退出码 5），可直接挂 CI；
- **引擎不同的基线拒绝比较**：fixture 产物与真实识别不是一回事，
  混着比会得出"换了模型反而变好了"这种没有意义的结论。

## 八、小样本：每个比例都附 Wilson 区间

本项目的样本量很小（金标集十几题、每类只有几题）。
一个"100%"很可能只是 n=3 的假象：

| 观测 | 点估计 | 95% Wilson 区间 |
|---|---|---|
| 5/5 | 100% | [56.6%, 100%] |
| 3/3 | 100% | [43.8%, 100%] |
| 14/16 | 88% | [64.0%, 96.5%] |

所以报告里**每个比例都带区间与样本量**。宁可让报告看起来"不够漂亮"，
也要把不确定性摆在明面上。

## 九、阈值校准：两次踩在同一个坑上

本节记录阈值是怎么定下来的。它比阈值本身更重要——**两次都栽在同一个错误上**。

### 坑：拿 RRF 分数做"置信度"判断

RRF 的分数是 `Σ w/(k+rank)`，k=60 时排名第 1 与第 20 只差约 27%，
而且多臂求和会把这个差距进一步压平。实测数据：

| 用途 | 结果 |
|---|---|
| 用它做**拒答阈值** | 阈值低拦不住、阈值高把相关结果也拦掉。改用**实词覆盖率**后，相关题 0.60~1.00、无关题 0.00，区分度是天然的 |
| 用它做**歧义检测的"分数接近度"** | 任意两个候选的分数比**恒在 0.95~1.00**，这条判据对每一对都成立，等于没写。歧义检测因此在 13 道题上误报 9 道 |

**结论：RRF 适合排序，不适合表达置信度或接近度。** 两处都改成实词覆盖率后：

- 拒答：相关题覆盖率 0.60~1.00，无关题 0.00
- 歧义：真歧义 1.00，只是沾边的干扰项 0.33~0.67 → 阈值取 **0.8**，正好切在中间

### 两个"度量本身错了"的坑（比代码 bug 更值得记）

索引层指标是**先接进评估、才第一次真跑**的。第一次跑出来的数字很难看
（CER 1.90%、数值召回 87.97%），排查后发现**识别是对的，是度量错了**。
这类错误比代码 bug 危险得多：它不报错、不崩溃，只是安静地给出一个
看起来像"识别质量差"的数字，而没有人会去怀疑标尺。

**① 换行被压掉，相邻两行的数字粘成一个。**

数值提取原先跑在 `normalize_for_cer()` 的结果上，而它用
`re.sub(r"\s+", "", ...)` 把**换行也压掉了**（对 CER 是对的，比对不该被换行影响）。
于是 `…Q/EXAMPLE 001—2026` 换行后接 `1  范围`，压成 `001—20261`，
正则把 `20261` 当成**一个**数——参考里的 `1` 被报成"漏掉"，
结果里多出一个 `20261`。同一行里 `1.0  1.0  1.5` 压成 `1.01.01.5`
也会被整串吃掉（小数部分允许 `.`）。

改法：数值提取用**保留空白与换行**的归一化，数字之间的边界就还在。
回归用例见 `tests/test_metrics.py::TestNumericFieldAcrossLines`。

**② 条号不在 `text` 里，被当成"没识别出来"。**

VLM 把条号放进结构化的 `clause_label` 字段，`text` 只剩正文
（「范围」而不是「1  范围」）。而 `plain_text()` 只拼 `text`——
于是这份文本表示**整个丢掉了条号**。后果有两层：

- 索引层：参考转写里写着「3.1」，OCR 文本里找不到 → 条号被报成漏识别；
- **跨引擎比对**：两引擎对**条号**的分歧恰恰是最该抓的高风险差异之一
  （错一个条号，答案就引到别的条款上），丢掉它等于把一路信号静默关掉。

改法：`plain_text()` 拼回 `clause_label`（正文已带条号的不重复补）。

**修完之后的对比**（同一份 GB/T 产物，同一个模型输出）：

| 指标 | 修前 | 修后 |
|---|---|---|
| 归一化 CER | 1.90% | **0.38%** |
| 字符准确率 | 98.10% | **99.62%** |
| 数值字段召回 | 87.97% | **96.67%** |
| 第 3 页数值召回 | 73.9% | **100%** |

**识别结果一个字节都没变**，变的只是度量。这也是为什么"先把索引层接进来真跑一次"
是必要的——一个从未跑过的指标，等于没有指标。

### 最终阈值与其依据

| 参数 | 取值 | 依据 |
|---|---|---|
| `min_coverage`（拒答主判据） | 0.45~0.60 按场景 | 相关题实测 0.60~1.00；标准件最严（0.60），金融 0.55 |
| `AMBIGUITY_MIN_QUERY_OVERLAP` | 0.8 | 真歧义 1.00，干扰项 0.33~0.67 |
| `min_top_score`（辅助判据） | 0.0（关闭） | 归一化融合分只作兜底，不参与主判 |

**这些值是在合成件（2 页、16 个片段）上标定的**，样本很小。
真实文档上应当重跑本节描述的过程重新校准，并把结果写回这里——
**阈值不是常数，是随语料走的**。

### 一次"假阳性比没有检查更糟"的实例

`clause_consistency` 一开始把答案里**所有带小数点的数字**都当成条号声明。
于是表格里的 AQL 值 `2.5` 被判成"答案提到条款 2.5，但证据里没有"，
一条完全正确的表格问答被拦下、触发修复、复检、最终拒答。

修法是要求条号必须**是文档里真实存在的条号**（传入 `known_clause_labels`）；
编造一个不存在的条号则由 `numeric_grounding` 兜住，不留缺口。

**一个把正确回答判成错误的检查，比没有这个检查更糟**——
它会训练使用者忽略所有告警。

## 十、为什么不引入 RAGAS / DeepEval 一类框架

| 理由 | 说明 |
|---|---|
| **主指标不可靠** | 同类框架以 LLM 评委为主；调研显示其在**金融长文本/表格场景 Context Recall 误判率报告高达 37%**。本文档正是表格密集 |
| **定义不可比** | "Faithfulness 在 Ragas 里与在 DeepEval 里不是同一个东西"。用别人的商标会掩盖定义差异 |
| **不可复现** | 换一个评委模型，分数就变。而"可复现"是本次交付的硬要求 |
| **依赖重** | 引入框架会带来大量传递依赖，与"三条命令可复现"的目标冲突 |

所以本项目的主指标全部是**确定性实现**：给定同样输入，结果必然一样，
可以单元测试，公式写在本文档里，评委模型只作可选交叉参考且必须标注局限。
