# 回答范围模式：strict 与 hybrid

- 状态：**已实现（2026-10-31）；契约在审计后收紧**，本文按收紧后的契约描述。
  设计契约见
  [`docs/reviews/2026-10-31-hybrid-mode-contract.md`](reviews/2026-10-31-hybrid-mode-contract.md)。
- 适用范围：Web 工作台（桌面 / 平板 / 手机）、`POST /api/ask`、CLI `docqa ask`。
- 一句话：**strict 是默认，引用/自检/拒答一字不改；hybrid 是显式可选路径，
  把"文档没有的通用知识"单独放进一个不可引用的段落——模型知识不是证据。**

---

## 1. 两种模式的边界

| 模式 | 文档能支持的内容 | 文档没有的内容 | 拒答 |
|---|---|---|---|
| `strict`（默认） | 只能来自证据，**逐句引用**（允许正常改写；引用/数值/条号自检把关） | 明确说"文档中未提及" | 现有六类不变 |
| `hybrid`（显式选择） | 仍**逐句引用**，且文档部分必须**逐字包含证据**（子串 gate） | 放在答案末尾 `【模型知识补充】` 段：**禁止引用**、**禁止声称文档写了** | `extraction_failed`、歧义、自检失败仍拒答；**不因"文档没有"拒答** |

三条不变量：

1. **默认永远是 strict。** 不带 `mode` 的旧请求、旧产物、旧客户端一律按 strict 处理。
2. **模式是逐问的。** 切换只影响下一问；已经显示在屏幕上的答案保留它**生成时**的模式，
   不会因为用户随后切换而被重标成另一种模式。
3. **模型知识不是证据。** 它不进入 `citations` / `evidence`，不参与引用有效性、
   数值落地、条号一致性与句级支撑度。

---

## 2. strict：默认路径，行为不变

- 有据生成、程序化自检（引用有效性 / 数值落地 / 条号真实性）、六类拒答与修复循环
  **全部保持原样**；strict 的报告里不会新增 `knowledge_label` 之类的检查项。
- strict **允许正常改写**：只要引用、数值与条号能对上即可；没有"逐字子串"要求。
- 文档里没有的内容，答案是"文档中未提及"——它本身是一个正确、可引用的答案，
  不是拒答。
- 检索没召回、覆盖率不足、最高分低于裕度等既有拒答条件照常生效。

---

## 3. hybrid：显式可选路径

### 3.1 文档部分

文档能支持的结论仍**逐句引用**，引用格式与证据头一致（PDF `[p.3 §3.6]`，
DOCX `[§3.6 ¶4]`）。文档部分必须**逐字引用证据原句/原词**：可以省略，或按原文顺序
拼接相邻片段，但**不得改写、不得插入解释**；解释、推断与通用知识只能放进
`【模型知识补充】`。`answer` 字段只放这部分正文；`citations` 只来自这里。

### 3.2 模型知识补充段

- 统一放在答案末尾，以**纯文本 marker** `【模型知识补充】` 开头。marker **只在单独
  成行时生效**（允许前后空白）；出现在句子中间/行内不算分界。以第一处单独成行的
  marker 为界，再次出现的 marker 会被剥离。
- **证据里的同名串会被替换**为 `【模型知识补充（文档原文）】`：文档原文恰好出现
  marker 时，它是**被引用的内容**，不是分段指令。替换**只作用于提示词里的证据文本**；
  chunk 原文、引用与数值落地仍用真实文本，不会被改写。证据开头/中间出现 marker
  都不会劫持分段。
- **C0/C1 控制字符统一在展示层净化**：唯一实现是 `models.sanitize_display_text`，
  已覆盖 **C0/C1 + bidi**（U+202A–202E、U+2066–2069）；API/CLI 出口的本地正则
  只是**幂等纵深**，不是唯一防线。覆盖字段：`answer`、`model_knowledge`、
  `refusal_detail`、`citations[].quote / rendered / clause_label`、
  `candidates[].citation`、`verification.checks[].detail / offenders`、
  `evidence.text`；保留 `\n` / `\t`。
- 该段**禁止任何引用标记**：`[p.N ...]`、`[§... ¶...]`、`[¶...]`、`[§...]` 等形态
  （含空格/大小写/全角变体）在展示前会被**全部剥离**并计数（见 §6）；
  剥离后为空则视为没有补充段。
- 禁止声称"文档中写了""标准规定"这类表述——补充段只能以通用知识口吻陈述。
- 文档明确未规定时，**先写"文档中未规定"**，再给补充段。
- 补充段是**纯文本**：前端不做 HTML 注入，也不为它生成引用 chip。

### 3.3 拒答语义（hybrid 仍会拒答）

hybrid **不因"文档没有 / 覆盖率低 / 检索分低 / 候选分差小"拒答**——这些正是它要
补位的场景。但下面三类拒答**不变，也不会用模型知识替代**：

| 情形 | 拒答理由 | 为什么不能用知识替代 |
|---|---|---|
| 存在**未识别页**（OCR 失败 / 缺少解析产物），且证据为空/覆盖率低，**或证据本身触及失败页** | `extraction_failed` | "没读到"不等于"没规定"；用知识补位会把可追溯性问题掩盖成答案。这些情况都在**起草之前**拒答 |
| 问题本身有 ≥2 个冲突解释 | `ambiguous_question` | 用户要选的是"问的是哪一个"，不是听两套知识 |
| 文档正文自检失败且修复无效 | `verification_failed` | 正文引用/数值/条号都不过门时，补一段知识只会让错误更难被发现 |

hybrid 在判定链里**跳过 4–7 步**（无证据、覆盖率不足、低分、候选分差），
前三步走完（且不触发下面的失败页前置）才放行生成。
**任何情况下都不会出现"hybrid 把拒答换成模型知识"**。

**零引用放行只有两个条件（缺一不可）：**

1. 文档正文为空**且** `knowledge_used=True`（确实给出了补充段）；或
2. 正文的**每个分句**都是**通用否定短句**，且按 `；;。` 切分后**每句都要匹配**
   精确白名单：

   > 文档 / 本标准 / 本文件 / 该文档 / 该标准
   > + 可选方位：中 / 里 / 内
   > + 未 / 没有 / 并未
   > + 规定 / 提及 / 涉及 / 包含 / 收录 / 给出 / 找到 / 说明 / 列出
   > + 可选：任何 / 相关 / 此项 / 该 / 上述
   > + 可选：内容 / 要求 / 信息 / 规定 / 说明 / 条款 / 事项
   > + 可选句号

   这是**精确模板匹配**（`is_generic_negative`），不是"含否定词"的启发式；
   白名单句子**不得含具体对象或谓词**。**具体否定 + 真实 citation 仍会被拒**：
   例如「文档中未规定冲击韧性要求。[p.1 §3.1]」不在白名单，也几乎不可能是证据的
   逐字段——"引用真实证据"只在**整句确实逐字来自证据**时成立。正确写法是通用否定
   （「文档中未规定相关内容。」）+ 具体说明放 `【模型知识补充】`，或引用证据原句，
   或切 strict。

「未规定 A；B 应采用合金钢」不放行（具体对象 + 肯定分句）；只有
`文档中未规定相关内容。` 这类不含具体对象的短句才合法。零引用不是"没出处"，
只允许出现在"整段只是在说文档没规定"的情形。

**明确例外**：`文档中未规定。` **无论有没有 citation 都可放行**——它是模型对
"未找到"的判断声明，不是具体证据；具体结论仍必须引用（或放进补充段）。若它附带
一个绑定不上的 citation，`doc_citation_marks` 仍会拒绝。

**`extraction_failed` 前置**：hybrid 下若存在识别失败页，且**证据为空/覆盖率低，
或证据本身触及失败页**，**在起草之前**直接拒答 `extraction_failed`——不花一次模型
调用，也不用模型知识替代"这页没读出来"。

**空输出不是成功**：文档正文与补充段都为空 → 起草失败，进入修复；修复后仍为空则
按 `verification_failed` **拒答**（`answer=None`）。它不是一条"模型没说什么"的
成功空答案；拒答沿用既有的响应契约（API 返回 `refused=true` 的拒答对象、CLI 打印
拒答面板），不会被当作答案放行。

### 3.4 没有生成模型时不可用

hybrid 依赖生成模型；未配置 `DOCQA_LLM_*` 时：

- **前端**：hybrid 选项 `disabled` / `aria-disabled`，提示"未配置生成模型"；
- **API**：`mode=hybrid` 返回 **400**，消息说明"hybrid 需要生成模型；当前未配置"；
- **CLI**：`docqa ask --mode hybrid` 报**配置错误**（退出码 2），提示缺哪一项、去哪配。

**绝不静默降级成 strict**——界面写着 hybrid、实际按 strict 答，是比报错更糟的错位。

## 4. 契约：API / CLI / 响应字段

### 4.1 API

```http
POST /api/ask
{"question": "……", "mode": "strict"}     # mode 可省略，默认 strict
```

- `mode` 只接受 `"strict"` / `"hybrid"`；非法值由 Pydantic 返回 **422**。
- `mode=hybrid` 且未配置生成模型 → **400**，`detail` 是
  `HYBRID_REQUIRES_LLM_MESSAGE` 的多行可操作文本（缺哪些 `DOCQA_LLM_*`、
  怎么配、系统不会静默降级）。
- **不新增端点**；只扩展现有响应的字段。

响应新增：

```json
{
  "answer_mode": "hybrid",
  "model_knowledge": "……",   // 只含补充段；strict 恒为 null
  "knowledge_used": true      // 实际出现了非空补充段
}
```

- `answer` 仍只放**文档正文**；`citations` 仍只来自文档正文。
- `evidence` 仍只含文档引用对应的片段。
- 旧响应缺这三个字段时，前端按 `strict` / `null` / `false` 容错。
- **状态码边界**：无产物 / 未就绪时 `POST /api/ask` 返回 **503**（`load_error`），
  不要误报成 400。**400 用于请求本身不合法**：`hybrid` 但未配置生成模型
  （`HYBRID_REQUIRES_LLM_MESSAGE`）、空问题、超长问题。
- `/api/status` 无论正常还是早退（`ready:false`）都带 `has_llm`；前端只在
  `has_llm === true` 时允许 hybrid（**缺字段按不可用处理**，不猜"已配置"）。

### 4.2 CLI

```powershell
uv run docqa ask "3.6 的斜度公差是多少？"                 # strict（默认）
uv run docqa ask "同类键的常见材料牌号有哪些？" --mode hybrid
```

- 非法 `--mode` 与"hybrid 但未配置生成模型"都在入口报**配置错误（退出码 2）**，
  提示里给出缺的 `DOCQA_LLM_*` 变量；不会落到某个默认分支。
- 人读输出第一行是「模式：仅文档 / 含模型知识」；补充段用独立的
  `模型知识补充` 面板打印，**不带任何引用**。
- 正文为空但补充段非空：答案区显示「文档中未找到可引用的依据。」——这是有效结果，
  不是错误态。
- `--json` 输出包含 `answer_mode/model_knowledge/knowledge_used`。

## 5. 前端交互（Web 工作台）

- **位置**：`ModeSwitch` 在输入区（Composer）**输入框上方**，桌面 / 平板 / 手机都可见，
  不藏进设置或抽屉。
- **形态**：分段胶囊「仅文档」/「文档 + 模型知识」；切换用 `transform`/`opacity`
  过渡，不硬切；下方一行边界说明随模式淡入淡出：
  - strict：「答案只来自检索到的证据」
  - hybrid：「文档内容仍带引用；模型知识会单独标注」
- **只对下一问生效**：请求进行中禁用切换；当前答案保留生成时的模式 chip
  （`仅文档` / `含模型知识`）；hybrid 且实际用了补充段时，卡片另带
  `已用模型知识` badge。
- **持久化**：`localStorage["docqa.answerMode"]`，首次默认 strict；初始化时同步读取，
  读写都包 try/catch（隐私模式下不可用也不影响使用）。未配置生成模型时强制按
  strict 发送，但**不覆写**已保存的偏好，等用户主动切换。
- **无障碍**：`role="radiogroup"` + 两个 `role="radio"`，左右方向键切换，Tab 可聚焦，
  有 `focus-visible` 环；`prefers-reduced-motion: reduce` 时去掉滑动/闪烁动画。
- **未配置模型**：`has_llm !== true`（缺字段也算不可用）时 hybrid 选项
  `disabled` / `aria-disabled`，下方显示「未配置生成模型」提示。
- **补充块**：与带引用正文分开渲染（虚线/浅色背景 + 信息图标），**纯文本**；
  `answer` 为空但补充段非空时，显示「文档中未找到可引用的依据」+ 补充块，
  不显示"模型没有返回正文"的错误态。
- 三视口（1440 / 768 / 390）无横向滚动、无 console error。

## 6. 自检与引用处理

- **只检查文档正文**。`model_knowledge` 不参与 `citation_validity`、
  `numeric_grounding`、`clause_consistency`，也不参与 `doc_sentence_support` /
  `doc_citation_marks` / `sentence_support`。
- **GATE `doc_sentence_support`（仅 hybrid）**：按**子句粒度**切分
  （`。！？!?；;，,：、` 与**所有视觉换行**：`\n`、`\r`、`\v`、`\f`、
  U+2028 LINE SEPARATOR、U+2029 PARAGRAPH SEPARATOR、U+0085 NEL），
  **引用标记归前一个子句**；**短句/逗号子句不再豁免**——
  每个实质子句都必须被**自身或同一句内最后一个带尾部标记的引用**覆盖：
  子句自带标记时只用自己的标记；
  没有标记时只借用**同一句最后一个带尾部标记的子句**的引用（借用源不必是最后一个
  子句；句子边界为 `。！？!?` 与上述所有视觉换行，**不跨句**）。尾标记后允许 0–2 个
  闭合包裹字符与空白（`）` `)` `】` `」` `』` `》` `”` `’`），因此
  `A，B（[§1 ¶2]）。`、`A，B [§1 ¶2]）。`、`A，B [§1 ¶2]”` 的句末引用同样可被
  同句借用；ASCII `.` 与 ASCII 引号 `"`/`'` 不支持（见 §7）。借用后仍须**逐字可证**——
  **去掉引用标记后的
  归一化文本，必须在所引证据的归一化文本里做段边界匹配**（不只是任意子串）。归一化把
  **边界字符**
  （空白、表格 `|`、句读标点、引号/书名号/括号）从匹配核心中剔除，但保留在 source
  里用于两侧边界判定；**单位、符号与限定词（mm / μm / ℃ / % / ± / 该 / 被 / 以上 /
  以下 / 不大于 / 不低于）保留在核心中**，任何差异都会被拒。连接词 `的 / 为 / 和 /
  按` **只在恰好构成一个 jieba token 时删除**（所以"行为 / 按钮 / 目的"不会被拆坏）。
  匹配要求**两侧段边界**：起点/终点必须在证据开头/结尾，或紧邻上述边界字符——即子句
  必须是 evidence 里**某一段或表格单元**的边界匹配；紧邻中文、字母数字或单位符号
  一律失败。因此**紧邻无空格的前缀删除会失败**（`不得使用铝` → `使用铝`）；但
  **空白/换行/表格单元分隔的否定前缀仍可能被单独引用**——`不得 | 使用铝`、
  `不得\n使用铝`、`不得 使用铝` 中，`使用铝` 的起点紧邻的是边界字符，会通过。
  这是已知残余（P2，见 T8 验证报告 §8 #2），**不要当成绝对安全**。
  截断数值/单位同样会失败（`0.5 mm` 不能冒充 `±0.5 mm`，`80` 不能冒充 `80 ℃`）。
  不再使用 token recall / 词面重叠作为放行条件。
  不过门会触发修复；修复后仍不过则拒答（`verification_failed`）。
  strict 仍走原有 advisory `sentence_support`、保留正常改写，检查列表与报告不变。
- **GATE `doc_citation_marks`（仅 hybrid）**：文档正文里的**每个 citation-like token
  必须绑定到已解析的 citation**；`[p.99 §9.9]` 这类未绑定伪标记直接失败，
  **不会回退到"全部 citations"或任意证据**。这条**不因零引用放行而跳过**——
  通用否定 + 伪引用同样失败。
- **这是有意的安全取舍，已知会误杀**：正常改写、单位同义写法（兆帕 vs MPa）、
  语序调整、以及单位/符号/限定词差异（± / ℃ / % / 以上 / 不大于……）都可能被判
  不过。**句号在引号内**（`“抗拉强度应大于等于 590 MPa。”[p.1 §3.1]`）可能被切分
  误杀；**词中间截取**（只取 `大于等于 590 MPa`）会被段边界拒绝——只能从段 /
  表格单元 / 词边界截取。段边界匹配能拦住**紧邻无空格**的"删除否定/限定前缀反转
  极性"（`不得使用铝` → `使用铝`），但空白/换行/表格分隔的否定前缀是已知残余
  （P2，见 §6/§7）。因为"词面相近但语义跑偏"无法用确定性规则可靠区分，hybrid 选择
  "宁可拒答也不放行无据子句"。hybrid 的文档部分必须**逐字引用证据原句/原词**；
  需要改写时请用 strict，或让模型先逐字引用原句、再把解释放进
  `【模型知识补充】`。
- **零引用放行只有两个条件（缺一不可）**：
  1. 文档正文为空**且** `knowledge_used=True`（确实给出了补充段）；或
  2. 正文的**每个分句**都是**通用否定短句**，按 `；;。` 切分后每句都匹配精确白名单
     （见 §3.3：文档/本标准/本文件 + 未/没有/并未 + 规定/提及/… + 可选限定 +
     内容/要求/… + 句号），且**不含具体对象/谓词**。

  具体否定（「未规定冲击韧性要求」）不再放行；「未规定 A；B 应采用合金钢」也不放行。
  **例外**：`文档中未规定。` 无论有无 citation 都可放行（模型"未找到"声明，不是
  具体证据；附带的伪 citation 仍被 `doc_citation_marks` 拒绝）。
  放行时 `citation_validity`（gate）通过，detail「文档正文无引用，补充段不参与文档
  自检」；句级支撑度按**「不适用」**处理（通过、不亮红）——没有引用就没有可比对的
  证据，照常打分只会是一个没有意义的红色告警。
- **ADVISORY `knowledge_label`**（不阻断；前端显示名「知识标注」）：
  - strict：不新增该检查，strict 报告完全不变；
  - hybrid 未使用补充段：通过，detail「未使用模型知识」；
  - hybrid 使用补充段：通过，detail「补充段已显式标注」；
  - 若补充段里剥离过引用：**不通过**（advisory），detail「补充段含 N 个引用标记，
    已剥离，不计入文档引用」——这是 prompt 失效的早期信号。
  - 伪引用的**变体**（空格、大小写、全角括号等）同样会被剥离并计数；补充段若
    **只含**伪引用，剥离后视为没有补充段，advisory 仍会报"已剥离"。
- **模型把知识混进正文且不标注**：正文会按 strict 的自检规则处理——没有引用的
  断言会被拦截/触发修复；修复无效则拒答。这是"纯文本 marker"方案的已知退化路径，
  不是漏检。

## 7. 已知限制

### 引用语义：只保证“逐字有据”，不保证片段相邻/同序（SEC-T1-04，重要）

hybrid 的引用覆盖粒度是**句子**：句末引用让同一句的多个肯定子句共用一份证据，
但门禁只逐个校验「每个子句能否在所引证据的**段边界**上逐字找到」。因此：

- 多个子句可以分别来自证据的不同位置，原文中间的内容可以省略；
- 子句的先后顺序可以与原文不同；
- 多标记并集（`[p.1] [p.2]`）允许拼出一段在任一 chunk 里都不连续的文字
  （SEC-T1-03，预存语义；契约要求多标记取并集）。

**引用不是“整句原文连读”的证据。** 需要核对上下文、顺序或完整性时，按引用
打开原文；合规 / 审计场景以原文为准（见 §8）。

- **marker 是纯文本** `【模型知识补充】`，不是结构化字段：模型可能写变体、写两次、
  写成行内或完全不写。只有**单独成行**的 marker 才是分界；写两次时只按第一处切分
  并剥离后一个；完全不写时退化为"正文里混了无引用内容"，由 `doc_sentence_support`
  / strict 自检兜底（见 §6）。证据中的同名串已替换为
  `【模型知识补充（文档原文）】`，不会劫持分段。
- **补充段引用剥离是展示层保护**，不等于模型理解了"不许引用"；剥离数量进 advisory。
- **逐字 gate 是安全优先的取舍，不是语义蕴含保证**：正常改写、单位同义写法
  （兆帕 vs MPa）、语序调整、单位/符号/限定词差异（± / ℃ / % / 该 / 被 / 以上 /
  不大于……）都可能被拒（已知误杀）；归一化把空白/表格 `|`/句读标点/引号括号当作
  **段边界字符**（不参与匹配核心，但用于两侧边界判定），连接词只按 **jieba token**
  删除 `的/为/和/按`（"行为/按钮/目的"不会被拆），**单位/符号/限定词保留在匹配核心**
  中。匹配要求**两侧段边界**，紧邻中文/字母数字/单位符号一律失败；截断数值/单位
  会失败（`0.5 mm` vs `±0.5 mm`、`80` vs `80 ℃`）。hybrid 的文档正文应尽量逐字
  引用；需要改写时切 strict，或让模型引用原句后再补充（更多误杀与残余见下）。
- **具体否定 + 真实 citation 仍会被拒**：只有 §3.3 的**通用否定白名单短句**可以
  零引用；「文档中未规定冲击韧性要求。[p.1 §3.1]」不在白名单，也不会因为带了一个
  真实引用就通过——它必须整句逐字来自证据，或改用 strict / 把具体说明放进补充段。
- **原文本身含引用字样时可能误判**：文档原文里若有 `[p.3]`、`[§3.6 ¶4]` 这类
  纯文本，模型逐字引用它时 `doc_citation_marks` 可能把它当作 citation-like token；
  若绑定不上已解析引用，会判失败。此时需换用不含该字样的原文片段，或切 strict。
- **段边界匹配仍有残余 (P2)**：紧邻无空格的否定/限定前缀（`不得使用铝`）会被拦住，
  但**空白/换行/表格单元分隔**的否定前缀仍可能被单独引用——`不得 | 使用铝`、
  `不得\n使用铝`、`不得 使用铝` 中 `使用铝` 的起点紧邻边界字符，会通过。不要把
  "段边界"当成绝对安全。**本次修复未改变这一残余（SEC-T1-06）。**
- **逐字 gate 的已知误杀**：句号在引号内（`“抗拉强度应大于等于 590 MPa。”[p.1
  §3.1]`）可能被切分误杀；词中间截取会被段边界拒绝；只能从段/表格单元/词边界
  截取。截取完整片段仍可能断章取义——但引文确实来自证据本身，补充段仍不是证据。
- **标记必须位于某个子句的尾部（F5 / SEC-T3-03）**：只有**子句尾部**的标记可被
  同句其它子句借用（其后可跟逗号或闭合包裹字符）。**与内容粘连的句首/句中引用
  不覆盖后续子句**：`[p.1 §3.1] A，B。`、`A [p.1 §3.1] 后续，B。` 里的后续子句
  仍会判「没有引用标记」——标记不在任何子句尾部时，无法确定后续子句引用的是哪
  一段，保守拒绝。注意 `[p.1 §3.1]，A，B。` **会通过**：纯引用子句自身就是一个
  「尾部带标记」的子句，可作同句借用源。
- **ASCII `!?` 是句子边界，可能误杀阶乘/混排写法（F6）**：`计算 n! 的值应符合
  规定 [p.1 §3.1]。` 会在 `n!` 处切成两句，后句没有引用而失败。这是契约定死的
  边界集合，暂不为「阶乘/感叹」做上下文区分。
- **ASCII `.` 与 ASCII 引号阻止句末引用借用（SEC-T1-05 / SEC-T3-01）**：
  `A，B [p.1 §3.1].` 里的 ASCII 句点既不切子句、也不在尾标记的闭合包裹容忍范围
  内，A 借不到引用而判失败；`"`/`'` 同理——它们不在段的边界字符集里，若当作闭合
  包裹会出现「借用源成立、但带标记子句自身永远不逐字」的矛盾，因此**不支持**。
  `.` 与数字小数点归一化冲突，不能全局加入边界字符；请用中文句读，或把引用放在
  `。` 之前。尾标记后超过 2 个闭合包裹字符同样不识别。
- **句号后带包裹的引用仍会被拒（R1 / SEC-T3-02，已知误杀）**：
  `本文件规定了……。[§1 ¶2]）`、`……。（[§1 ¶2]）` 这类「句号后引用 + 闭合包裹」
  的写法仍失败——前句领引用合并（leading merge）只吞标记本身、不吞包裹，残留的
  `）`/`（…）` 会成为伪子句。这是保守失败（不会放行无据内容），但自然写法被误杀；
  修法是让合并一并消费闭合包裹，届时同步更新本段与对应测试。
- **证据原文含视觉换行时需逐段引用（R2）**：视觉换行（`\r`/`\v`/`\f`/U+2028/
  U+2029/U+0085）一律是句子边界（SEC-T1-01 的安全修复）。代价是当**证据本身**
  含这些字符时，逐字引用整句会被切成多句，前置子句失去引用而失败。请按行/段分别
  引用，或改用 strict；正常 PDF/DOCX 解析会把换行统一成 `\n`，命中概率较低。
- **无条号文档上的伪条号可借页级回退绑定（SEC-T1-02，预存）**：证据 chunk 没有
  条号时，`[p.1 §9.9]` 会按页回退绑定到该页的真实 citation，无条号 PDF 因此
  可能通过；有条号集合的文档仍会被 `citation_validity` 拦下。收紧会影响正常的
  无条号 PDF，列为已知残余。
- **多标记并集允许跨 chunk 拼接（SEC-T1-03，预存）**：`[p.1 §3.1] [p.2 §3.2]`
  会把两个 chunk 拼接后做整段匹配，子句的每部分各自逐字、拼起来却不在任何一处
  相邻。详见本节开头「引用语义」。拼接顺序固定为**首次出现顺序**（marks →
  citations → `evidence_chunk_ids`），不再受 `PYTHONHASHSEED` 影响（SEC-T3-04）。
- **展示净化已统一覆盖 bidi**：`models.sanitize_display_text` 现在同时剥离 C0/C1
  与 bidi（U+202A–202E、U+2066–2069）；API/CLI 的本地正则只是**幂等纵深**。
  其它绕过该函数直接输出原始文本的新通道仍需自行净化。
- **伪 citation 标记会直接判失败**：`[p.99 §9.9]` 等未绑定到已解析 citation 的标记
  触发新增 GATE `doc_citation_marks` 失败，**不回退到"全部 citations"或任意证据**，
  且**不因零引用放行而跳过**——否则一个编造的 locator 就能借用真实引用蒙混过关。
- **模型知识可能过时或错误**：它没有证据链，也没有文档版本约束；**不能作为合规 /
  审计的唯一依据**（见 §8）。
- hybrid 的答案质量取决于生成模型；本项目的确定性指标（引用、数值、条号）仍只覆盖
  文档正文。
- **注入命中不进问答**：ingest 阶段的 `injection.hits` 只记录在产物里，
  **未进入答案展示与拒答策略**——检出可疑指令不会自动改变作答行为。
- **没有 CSP / 安全响应头**：Web 服务未配置 `Content-Security-Policy`、
  `X-Content-Type-Options` 等，部署时应在反向代理补。
- **没有按客户端限流**：只有全局并发上限（问答 2 / 上传 1），同一客户端可以占满。
- strict prompt 相对更早 HEAD 的 DOCX 引用改动（`[§… ¶n]`）**不是本功能引入**，
  属于既有演进；hybrid 没有改动 strict prompt。

## 8. 使用边界（写给读者）

- **模型知识不能作为合规 / 审计的唯一依据。** 涉及标准条款、合同义务、数值限值时，
  以**文档正文与引用**为准；补充段只能当线索。
- 需要**只依据文档、不引入任何模型知识**时，用 **strict**（默认；允许正常改写）；
  hybrid 的文档部分虽然逐字引用证据，但补充段仍是模型知识，不能当证据使用。
- 拒答在 hybrid 下依然会发生（未识别页 / 歧义 / 自检失败），这是**可追溯性的底线**，
  不是功能缺失。

## 9. 与 strict 的兼容性

- 默认请求、旧客户端、旧产物、旧报告全部按 strict 处理，行为不变。
- hybrid 是新增路径：新增 prompt、新增响应字段（带默认值）、新增 **GATE
  `doc_sentence_support` / `doc_citation_marks`** 与 **ADVISORY `knowledge_label`**
  （都只在 hybrid 出现）；
  strict 的 prompt、检查项与报告输出**不新增任何内容**。
- 验收基线：现有全量测试不回归；hybrid 的失败路径（无 LLM、非法 mode、
  `extraction_failed`、歧义、自检失败、伪引用剥离）各有测试覆盖。
