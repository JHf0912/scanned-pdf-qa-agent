# 金标扩标注与「过度拒答」诊断

- 日期：2026-11-03
- 范围：给真实文档金标 `data/golden/qa.jsonl` 补齐 `relevant_chunk_ids`（此前 n=0，
  检索层指标在真实文档上永远是空）；并对"过度拒答"做逐题定位，判断能否用改阈值修复。
- 约束：`--no-llm`（抽取式、确定性）复测，用于可复现的基线；不改生产阈值。

## 1. 做了什么：给真实文档金标补 `relevant_chunk_ids`

之前 `qa.jsonl`（GB/T 1568，18 题）**没有** `relevant_chunk_ids`，所以检索层
Recall/MRR/nDCG 都是 `n=0`（README 已如实写"不是没算，是没标"）。

本次按**内容**标注（不按检索器输出标，避免循环论证）：对每道题，取 `citation_pages`
内、文本真正包含答案关键词（`must_contain`）的 chunk，写成**短 id** `p{页}:c{序}`
（`_expand_relevant` 用后缀匹配，抗 `doc_id` 变化与产物重建）。

- 标注 12 题：C1–C5、T1–T4、G2、O2、M1。
- **不标**：G1（否定题，正确答案"未规定"是推断，没有"含答案的片段"）、O1（见 §3，
  含答案的前言被切进了封面 chunk，内容定位错位）、N1–N3/A1（拒答题，本就不参与检索层）。
- 原则：没把握的题**不标**，而不是拿页码近似——否则 Recall 会被拔到接近 1，数字失去信息量。

## 2. 复测结果（`docqa eval --no-llm`，真实文档）

检索层：**n 从 0 → 11**（真实数字，不再是空）

| 题型 | n | Recall@10 | MRR | nDCG@10 |
|---|---|---|---|---|
| clause | 5 | 100% | 0.800 | 0.852 |
| table | 4 | 100% | 1.000 | 1.000 |
| multi_hop | 1 | 100% | 1.000 | 1.000 |
| ocr_stress | 1 | 100% | 0.500 | 0.631 |
| **总体** | **11** | **100%** | **0.864** | **0.899** |

拒答：`refusal_precision = 0.60`、`refusal_recall = 0.75`；总体 accuracy（抽取式）0.4444。

## 3. 「过度拒答」逐题定位（这才是关键）

把 `refusal_precision=0.60` 拆开看，**误拒只有 2 题**，且原因不同：

| 题 | 现象 | 根因 |
|---|---|---|
| **T4**（表头分成哪几类键） | 应答应却 `not_in_document` 拒答 | 表头枚举类问题；抽取式的检索/覆盖判据没把表格 chunk 顶上来 |
| **O1**（历次版本 1979/1997） | 应答应却 `verification_failed` 拒答 | **真缺陷**：前言页（page 2）OCR 有 `1979/1997`，但 page 2 **一个 chunk 都没有**——跨页 section 沿用首块页码，前言被并进了封面 chunk `p1:c1` |
| **N2**（键槽深度，应拒） | 反而作答了（`refusal_recall` 的 FN） | "键槽"字样可能命中别的片段，覆盖判据放行 |

O1 的证据（可复现）：
- `ocr.json` page 2 有 `p2-b13「本标准所代替标准的历次版本发布情况为：」`、
  `p2-b14「——GB 1568—1979、GB/T 1568—1997。」`；
- 但 `load_result(...).chunks` 里 **没有任何 `page_no==2` 的 chunk**；`1979/1997`
  只出现在 `p1:c1`（封面 + 前言的合并 chunk）。

## 4. 结论：**不是"调低阈值"能修的**

- 误拒的两题，一题是**结构性切分缺陷**（多页 section 沿用首块页码，导致前言并入
  封面 chunk、page 2 无独立 chunk），一题是**表格/词面检索**不足；把 `min_top_score`
  或覆盖率阈值调低，只会同时让 N2 这类"该拒"的题被放行（precision 更差），
  是用一个错误换另一个错误。
- 真正对症的修法，代价不同：
  1. **切分按页断开 section**（修 O1 的根）：让每个 chunk 落在单一页、前言单独成片。
     影响面大——chunk id 会变、所有金标短 id 与新基线都要重算；属结构性改动，需单独排期+回归。
  2. **表格/词面检索增强**（修 T4 一类）：补表格线索词、或对表头类提问做行/列标题匹配。
     影响面中等，可单独评估。
  3. **抽取式固有限制**（否定/枚举/多跳综合）：需要生成模型，不是检索或阈值问题。

## 5. 建议下一步（需你定优先级）

- 若要动**根因**：先做「切分按页断开」——它能同时改善 O1 的误拒、跨页引用的页码正确性、
  以及 bbox 跨页问题（现在一个 chunk 可能跨页，页图高亮只能取被引页）。但要接受
  chunk id 变化与基线重建。
- 若只要**低风险收益**：先做「表格检索增强」并扩充表格类金标题。
- 在此之前，`refusal_precision=0.60` 应继续**如实呈现在报告里**，不掩盖。

## 6. 实施结果（选择 A：切分按页断开）

已按 A 实施：`chunker._blocks_to_sections()` 现在**遇到新页先冲刷**（跨页 clause
沿用条号、拆成两条各自定位到本页）。已重算全部 PDF 产物的 `chunks.jsonl`
（不重跑 OCR），并按内容重标注 `qa.jsonl` 的 `relevant_chunk_ids`。

**结构性效果（确定）**：
- `gbt1568`：31 → 33 chunks，**page 2 现在有独立 chunk**（此前整页缺失）；
  O1 的「1979/1997」现在能被检索到（`relevant_chunk_ids` 命中 `p2:c2`）。
- 检索层真实文档：n=11 → **n=12**，Recall@10 100%（MRR 0.864→0.819，语料仅几十段，
  不具统计意义）。

**真实（LLM）路径验证**（`build_llm_provider`，各 1 次调用）：
- O1「历次版本」→ **answered**：`…GB 1568—1979、GB/T 1568—1997 [p.2 ¶2]`（引用第 2 页）；
- C1「范围」→ **answered**：`…技术要求、验收检查、标志与包装 [p.3 §1]`。
即 **O1 类误拒在真实生成路径上已修复**。

**`--no-llm` 抽取式路径仍然噪声大**：抽取式会把多个召回片段拼成整段答案，答案里出现
3.3/3.4/3.5 等条号而引用集未覆盖 → `clause_consistency` 误判，导致 C1/O1 在该路径
仍显示拒答。这是**抽取式拼装**的固有问题，与切分无关；`--no-llm` 指标只用于回归。
因此：demo fixture 基线 `data/baselines/demo_fixture.json` 复跑**无下滑**（`与基线相比无下滑`），
无需重建；`qa.jsonl` 的真实文档检索指标按新切分重算（见上）。

结论修订：**切分按页断开是正确且必要的修法**（修 page2 丢失、跨页页码、跨页 bbox）；
"过度拒答"在真实生成路径上已消除，在抽取式路径上属于另一类（拼装）问题，另行评估。
