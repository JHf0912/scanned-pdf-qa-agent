### 1.2 威胁模型

- 攻击者/出错模型**完全控制答案正文**（含标点、换行、Unicode 控制符、引用标记的位置与数量），但 `citations` 由 `parse_citations()` 从答案解析并受 `citation_validity`（真实且已召回）约束。
- 安全属性（契约 §3.2）：**每个肯定子句必须是其所引用证据的段边界逐字子串**；引用覆盖粒度可以放宽到「句」，但逐字性、绑定真实性、不跨句三条不得放宽。
- T1 新增的唯一自由度：**无标记子句用哪一份证据做逐字校验**（同句最后一个子句的尾部标记）。任何新放行都必须仍满足「逐字 + 绑定真实 + 同句」。

## 2. 结论

1. **P0/P1：无新增；与 T1 可触及路径相关的既有 P0/P1 载荷（NEW-2 / NEW-7 / NEW-8 / NEW-9 / NEW-11）复测保持 CLOSED。** T1 没有放宽逐字门禁：借用来的引用仍走原 `_verbatim_match()`；伪引用/绑不上的标记仍失败；跨句不借用；否定前缀/单位截断/短句豁免的旧攻击仍失败（见 §4）。与本次改动无关的历史载荷未重跑（它们不经过 `doc_sentence_support` 的新增覆盖路径，且 179 个 hybrid 用例全绿）。
2. **可放行 T1。** 没有发现「无标记子句借到引用后、内容不是所引证据逐字内容」的路径；随机差分 3 万条 0 违例。
3. **6 项 P2**（详见 §3）：
   - 其中 2 项**预存**、非 T1 引入（伪条号在无条号文档上的页级回退、跨 chunk 并集拼接）；
   - 1 项是 T1 直接产生的**展示/归属不一致**（`\r` / U+2028 / U+2029 / U+0085 不是句子边界）；
   - 1 项是**契约已接受**的语义残余（单句末引用下的片段省略/重排）；
   - 1 项是**可用性误杀**（引号/括号/ASCII 句号阻止借用），非安全问题；
   - 1 项是**已文档化**的否定前缀残余，T1 未改变。
4. 建议：T3 至少修 P2-1（Unicode/CR 句子边界，改动小、可测试）；P2-2/03 建议修或显式接受；P2-4/05/06 写入 `docs/hybrid-mode.md` 与发布说明。

### 3.1 SEC-T1-01 详情（唯一的 T1 直接 new-behavior）

```text
answer : 抗拉强度应大于等于 590 MPa，\u2028通常采用调质处理 [p.1 §3.1]。
evidence: 3.1 抗拉强度应大于等于 590 MPa，通常采用调质处理。
新实现 : check_doc_sentence_support passed=True；完整 verify() gates_passed=True
对照   : 把 \u2028 换成 \n → failed（子句「通常采用调质处理」没有引用标记）
对照   : 前半句不逐字（一般通过热处理保证）→ failed（仍逐字门禁）
```

根因：`_SENTENCE_BOUNDARY_CHARS` 只有 `。！？!?\n`，`\r`、U+2028/U+2029（Unicode 行/段分隔符）、U+0085（NEL）都不算句子边界；而它们常被渲染器当作换行。于是「尾引用在下一视觉行」时，借用仍按同句成立。
**影响有限**：被借用引用的证据里必须逐字包含前一子句（E2 已证伪「无据放行」），所以不是无据断言；但「引用 chip 在下一行却覆盖上一行」会造成归属误读。`docs/hybrid-mode.md:220` 写的是「与换行」，实现只认 `\n`，属实现/文档不一致。建议按 P2 修。

### 3.2 SEC-T1-02 详情（伪条号 + 无条号文档）

```text
Chunk: page=1, clause_label=None, text="抗拉强度应大于等于 590 MPa。通常采用调质处理。"
answer: 抗拉强度应大于等于 590 MPa，通常采用调质处理 [p.1 §9.9]。
complete verify()（known_clause_labels=∅）: gates_passed=True
complete verify()（known_clause_labels={"3.1"}）: FAIL citation_validity「引用标注了文档中不存在的条款 9.9」
```

`_citations_for_mark()` 在「页匹配存在、条号子集为空」时回退到整页 citations（`verify.py:608-616`），因此 `[p.1 §9.9]` 能绑定到该页的真实 citation。该回退是**既有设计**（`parse_citations()` 也按页回退并保留原条号）；T1 只是让一个句末伪条号也能覆盖前面无标记子句。正常带条号的文档会被 `citation_validity` 拦下；风险集中在无条号 PDF。建议修或在发布说明列出。

### 3.3 SEC-T1-03 详情（跨 chunk 并集拼接）

```text
p1 text: "3.1 检验项目应按表 1。"
p2 text: "3.2 抗拉强度应大于等于 590 MPa。包装标志应符合规定。"
answer : "1 3.2 抗拉强度应大于等于 590 MPa，包装标志应符合规定 [p.1 §3.1] [p.2 §3.2]。"
结果   : gates_passed=True
```

子句 compact 为 `13.2抗拉强度应大于等于590MPa`，在 `p1 + " " + p2` 的 compact 串里连续（p1 的 `。` 与 join 空格都被剔除），左边界是空格、右边界是 `。`，于是被判「逐字」。**已确认该能力预存**：把两个标记放进同一子句（`1 3.2 … [p.1] [p.2]`）时，重建的 T1 前实现同样通过。T1 仅让它能以「借用句末双标记」的形式出现。契约要求多标记取并集，故列为 P2 残余；若要收紧，应改为「借用只取单个标记」而非改逐字匹配。

### 3.4 SEC-T1-04 详情（片段重排/省略）

```text
evidence: 3.1 抗拉强度应大于等于 590 MPa。包装标志应符合规定。
answer  : 包装标志应符合规定，抗拉强度应大于等于 590 MPa [p.1 §3.1]。
结果    : gates_passed=True（两句顺序被对调）
```

这是逐字子串门禁的固有语义（T1 前给每个子句各自加引用也能通过），契约 §3.2 明确只保证「每个被覆盖子句逐字可证」。但 `docs/hybrid-mode.md:45` 又写了「按原文顺序拼接相邻片段」——建议在发布说明中明确「引用只保证子句级逐字，不保证相邻与顺序」，避免用户把它理解成整句原文。

### 3.5 SEC-T1-05 详情（误杀，不是安全洞）

- `A，B [p.1 §3.1].`：ASCII `.` 既不是切分符，也不在 `_TRAILING_MARKS_RE` 的容忍范围；A 借不到引用，B 的内容带上 `.` 后也不再逐字 → 整句拒绝。
- `（A，B [p.1 §3.1]）` / `A，B [p.1 §3.1]”`：闭合标点阻止借用 → A 判「没有引用标记」。
- `A，B [p.1 §3.1]，C。`：最后子句 C 无标记 → 同句无「尾部标记」可借 → A 与 C 都失败（契约要求的保守行为）。
- 这些在 T1 前同样会失败（旧实现连 B 都需要自带标记），**不是回归**；只是说明本次修复尚未覆盖这些自然写法。

> hybrid 模式现在按「句」覆盖引用：句末引用可覆盖同一句的逗号子句（`A，B [p.1 §3.1]。`），但每个子句仍必须是被引证据的逐字内容；引用不跨句。引用只保证「每个子句逐字有据」，不保证引用所覆盖的多个片段在原文中相邻或同序（可省略、可拼接）。列举型/引号/括号后置引用等自然写法可能仍被保守拒绝。
