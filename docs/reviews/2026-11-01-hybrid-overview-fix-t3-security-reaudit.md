### 1.2 威胁模型

- 模型/攻击者完全控制答案正文（含所有标点、换行、Unicode 控制符、引用位置、闭合包裹字符），`citations` 由 `parse_citations()` 从答案解析并受 `citation_validity` 约束。

- T3 新增的两个自由度必须逐个证明不会破坏该属性：
  1. 闭合包裹字符只应影响**尾标记识别**，不能把实质内容藏在标记后；

## 2. 结论

1. **P0/P1：无新增。** T3 三项修复均未放宽逐字门禁：
   - 所有借用（含 F4 的「最后一个带标记子句」）仍走原 `_verbatim_match()`；
   - 闭合包裹只识别尾标记，实质内容无法藏在标记后；
   - 新增视觉换行全部成为句子边界，只收紧不放松；
   - 伪引用、跨句借用、否定前缀、单位截断、短句豁免仍失败（见 §4）。
2. **SEC-T1-01 CLOSED**：`\r`/`\v`/`\f`/U+2028/U+2029/U+0085/连续换行在两个方向（引用在前/引用在后）都不再跨视觉行借用；T1→T3 差分中 15 个载荷由「旧实现通过」变为「T3 拒绝」。
3. **SEC-T1-05（括号/引号部分）已修**：`A，B（[§1 ¶2]）。`、`A，B [§1 ¶2]）。`、`A，B [§1 ¶2]”` 均通过；非逐字的前半/带标记子句仍失败。
4. **F4 已修且安全**：`A，B [§1 ¶2]，C` 中 C 逐字时通过、非逐字时失败；借用源取「最后一个带标记子句」（不是任意一个）；跨句仍不借。
5. **SEC-T1-02/03/04/05/06** 维持既有残余；SEC-T1-04 已写入 `docs/hybrid-mode.md` §7（不保证片段相邻/同序），SEC-T1-02/03/05/06 亦已写入 §7。
6. **新发现 1 项预存 P2（SEC-T3-04）**：多标记/多 chunk 证据的并集顺序来自 `set` 迭代，受 `PYTHONHASHSEED` 影响，导致同一输入 pass/fail 不稳定；不是 T3 引入，但违反模块「确定性 gate」的承诺，建议修复。

### 3.1 SEC-T3-04 说明（为何与本次复测相关）

`_evidence_text_for_marks()` 把多个标记/多个 `evidence_chunk_ids` 收进 `set[str]`，再用 `" ".join(... for cid in ids)` 拼证据。`set` 的迭代顺序依赖字符串 hash 种子，于是：

- **多标记并集（SEC-T1-03 残余）**：同一拼接句在一个顺序下可匹配、另一个顺序下不匹配；
- **DOCX 长段落切片**：`evidence_chunk_ids` 本来就是为了把被切断的同一段拼回来；跨越切点的合法逐字子句同样会因顺序而随机失败/通过。

这不是 T3 引入的（T1 报告中的 D1 观测「gates_passed=True」也只是某个 hash 顺序下的结果），但 T3 的 F4 让更多子句走并集路径，增加了触发面。安全上仍不超出「所引证据并集」的既有语义，但**可复现性**是这套确定性 gate 的核心承诺，建议修。修复只改证据拼接顺序，不改变逐字匹配规则。

## 4. Bypass 结果（对应派工问题）

### 4.1 三项修复是否引入新的无据放行/跨句借用/伪引用绑定

| 验证 | 结果 |
|------|------|
| 112 个定向用例 | **0 个期望不符** |
| T3 vs T1 差分：T3 新增通过 | 13 个，全部是预期修复（7 个闭合包裹、4 个 F4、1 个通用否定源、1 个纯引用子句）；每个都配了「借用后非逐字」反例，**全部失败** |
| T3 vs T1 差分：T3 新拒绝 | 15 个，全部是 SEC-T1-01 的视觉换行（`\r`/`\v`/`\f`/U+2028/2029/NEL/`\r\r`，两个方向），符合预期 |
| 20,000 条随机答案 | 切分 oracle 偏差 **0**；new-pass 1,054 条，独立 oracle 复核违例 **0** |
| 伪引用 + 闭合包裹 | `[p.99 §9.9]）`、`[p.99 §9.9]）[p.2]`、全角 `［p.99］` 均失败（`doc_sentence_support` 绑定失败 / `doc_citation_marks` 失败） |
| own-mark 优先 | `A [p.2]），B [p.1]。` 中 A 仍只按 p.2 判定，不能借 p.1 |
| 跨句 | 引用在前/在后、`\r\n`/`\r\r`/`\n\n`/混合句末标点+换行均不借用 |

### 4.2 闭合包裹正则能否把内容藏在标记后

| 载荷 | 结果 |
|------|------|
| `A，B [p.1]）C` | 失败：`_trailing_marks` 为空（C 非闭合字符），A 无引用；B 自身内容含 `）C` 也不逐字 |
| `A，B [p.1]）））` | 失败：最多 2 个闭合字符，3 个不识别 |
| `A，B [p.1]）"后续` | 失败：不是尾标记；B 内容非逐字 |
| `A，B [p.1]）[p.2]` | 只借**最后一个**标记 `[p.2]`：A 仅在 p.1 时失败；A 在 p.2 时通过 |
| `A，B [p.1][p.99]）` | 失败：两标记都参与绑定，`[p.99]` 绑不上 |
| `A，B [p.1]）［p.99］` | 失败：`doc_citation_marks` 抓出全角伪标记 |
| `A，B（[p.1]）。`、`[p.1]）。`、`[p.1]”`、`[p.1]））`、`[p.1] ）】`、`[p.1]”’`、`[p.1]】` | 通过（借用源成立），且非逐字前半/带标记子句的反例均失败 |
| ASCII `"`/`'` 作闭合 | 借用源成立，但带标记子句逐字失败（见 SEC-T3-01） |

**结论：闭合包裹只影响尾标记识别，无法藏实质内容。**

### 4.3 F4：最后一个带标记子句借用

| 载荷 | 结果 |
|------|------|
| `A，B [p.1]，C`（C 逐字） | 通过（A、B、C 均逐字） |
| `A，B [p.1]，C`（C 非逐字） | **失败**，offender 点名 C |
| `A，B [p.1]，文档中未规定。` | 通过（通用否定子句不持有标记，但保留借用源） |
| `A，B [p.1]。C` | 失败（C 是新句，不借） |
| `A [p.1]，B` | 通过（B 借 A 的尾部标记；A/B 均逐字） |
| `A，B [p.1]，C [p.2]`（A 只在 p.1） | **失败**（源是最后一个带标记子句 C 的 p.2，不是 p.1） |
| `A [p.1]，C [p.2]，B`（B 只在 p.1） | **失败**（后置借用者用的是 p.2） |
| `A，文档中未规定 [p.1]，B`（B 非逐字） | **失败** |
| `[p.1]，A，B` | 通过（纯引用子句是合法的尾部标记子句；见 SEC-T3-03 文档措辞） |
| `A [p.1] 后续，B`（标记不在子句尾部） | 失败（不作为借用源） |
